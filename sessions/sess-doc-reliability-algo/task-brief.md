# Task Brief — sess-doc-reliability-algo

Date: 2026-11-12
Mode: fallback (per fallback/index.md v0.6.0)
Project stage: Specification (no code implementation of Documenter/Moderator yet; fallback is frozen and must not be modified).

## Goal

Evaluate a proposal to increase documentation consistency reliability by moving mechanical actions from AI judgment to deterministic algorithms. Decide per subject: agree / conditionally agree / oppose, with findings tied to subject IDs.

## Background

Current pain points: version stored twice (doc header `Version:` + manifest `version:`) and can drift; `Last Modified` maintained by AI; changelog entries typed by AI; manifest edited by AI on create/rename/delete; compliance checks (line count, anchors, changelog existence, manifest parity) performed by AI skill. Existing precedent: `tools/check_parity.py` already deterministically checks manifest↔disk version parity (audit rule 6). Documenter service spec (`docs/en/documenter-service/*`) envisions deterministic pure-core but is unimplemented (Tier 0-1 read-only MVP, spec only). AGENTS.md §2.2 declares the manifest "single source of truth".

## Proposals (subjects)

- SUBJ-001 — **Manifest as generated artifact**: document frontmatter becomes formal machine-readable YAML; `docs-manifest.yaml` fully regenerated by `tools/gen_manifest.py`; nobody hand-edits manifest. AGENTS.md §2.2 convention changes accordingly.
- SUBJ-002 — **Deterministic validator + git pre-commit hook**: extend check_parity.py into a CLI suite of audit rules 1–6 from mvp-interfaces.md (line count ≤200, changelog existence, cross-ref anchors, manifest parity, naming, schema); run as pre-commit so inconsistent commits are structurally blocked. Works today, no Documenter needed.
- SUBJ-003 — **Mechanical fields derived, not authored**: `Last Modified` derived from git; version bump (patch/minor/major per AGENTS.md §7.5) classified deterministically from canonicalized diff, ambiguous cases escalate to operator; changelog entry auto-generated from (old ver, new ver, reason string).
- SUBJ-004 — **Parameterized scripts for safe-tier operations**: AI only dispatches commands like `bump_version.py --id X --kind patch --note "..."` which atomically (temp+rename) performs bump + changelog + manifest regeneration. "Procedural Documenter" predating real service; becomes its pure core later.
- SUBJ-005 — **Spec/AGENTS impact**: required edits to AGENTS.md §2.2 (manifest no longer hand-maintained single source of truth but generated index), possibly documenter-service/configuration-guide.md (hash store references manifest); consistency with Documenter MVP scope (which is read-only — does local tooling conflict?).
- SUBJ-006 — **AI/human residual boundary**: semantic content, split-point choice, glossary term novelty, translation, and reason strings stay with AI/operator; no algorithmic attempt at semantics.
