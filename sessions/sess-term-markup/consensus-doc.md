**Roster:** Architect, Reliability & Security Specialist, Human-Centric Designer, Operations Engineer
**Rounds:** 1 discussion round (per task brief)

## Decision

Исходная постановка отклонена, направление идеи — принято в суженном виде.

Глоссарий (`docs/en/glossary/index.md`) остаётся единственным источником истины для определений. Реестр терминов допускается **только** как производная, полностью пересобираемая read-only проекция (`derived: true`), собираемая лениво внутри `audit()`; он не заменяет глоссарий и не входит в changeset. Разметка `__term__` / `_term_` **отклонена**; разметка сайтов использования возможна лишь в отдельной фазе B и только при неконфликтующем с Markdown синтаксисе и измеренной выгоде.

## Rationale

- **Единогласно (4/4):** автономный реестр = второй источник истины с молчаливым расхождением. Механизм отказа: `audit()` проверяет корпус тем же реестром, поэтому расхождение реестра и текста даёт `clean`, а не finding (A-01, R-01/R-02, HCD-02, O-01).
- **3/4 (A, R&S, HCD):** `__term__`/`_term_` — это Markdown bold/italic; в корпусе массово используются inline-code идентификаторы (`audit_id` ×19, `allowed_operations` ×17, `target_id` ×15, `change_type` ×12), а разметка визуально неотличима от выделения и машинно не снимается.
- **3/4 (A, R&S, Ops):** правка `__term__` не входит в нормативный перечень Mechanical Edit (7 пунктов), значит её derived floor обязан быть `review`; при авторитетном реестре однострочная правка определения расходится по всему корпусу без попадания в `review`.
- **2/4 (A, R&S):** шестой rename (реестр) разрушает фиксированный Commit Order и не покрыт ни одной из трёх ветвей cold-start-реконструкции (§Safety Protocol #9).
- **Принятый выход (convergence R&S + Ops):** ленивый rebuild внутри `audit()` снимает блокер «писателя реестра не существует»; отдельный демон/watcher не требуется, запрет §Purpose не нарушается.
- **Не доказано:** что чтение глоссария (164 строки, 56 терминов) сегодня мешает агентам. Ни одна роль не подтвердила наличие проблемы, которую решает разметка.

## Conflicts & Disagreements

Единогласных оппозиций по одним и тем же subject нет. Одно нерешённое расхождение требует решения оператора:

- **SUBJ-006 / критерий перехода к фазе B.** Architect: «разметку вводить, если фаза A подтвердила ценность индекса» (severity medium). HCD + Ops: «ценность индекса не влечёт ценность разметки; обязателен отдельный замер текущей стоимости работы агентов с глоссарием» (severity medium). Равная серьёзность, разные действия → требуется решение оператора. Рекомендание ролей — позиция HCD/Ops.

Heuristic promotion candidates (зафиксировано, решение за оператором):
- Конвергенция двух независимых `medium` по query-интерфейсу (Architect A-06 + R&S R-04) → **повышено до high** в ходе раунда 1, подтверждено Ops.
- Конвергенция `high` по синтаксису (A-02 + R-05 + HCD-01/03) → блокера для любого варианта с разметкой.

## Reservations

**Architect**
- SUBJ-004: если оператор всё же настаивает на авторитетном реестре, это влечёт изменение зашитого пути чтения глоссария в неизменяемом скилле и правила AGENTS.md §4.2 — оба вне рамок сессии.
- SUBJ-002: идентичность термина (surface form vs lemma vs concept, английские плюрали, русская морфология) не определена; без правила реестр либо дробится по словоформам, либо сливает разные понятия.

**Reliability & Security Specialist**
- SUBJ-002: реестр — доверенный канал доставки текста в контекст агентов; без provenance-меток ошибочное или враждебно сформулированное определение размножается по всем сессиям.
- SUBJ-007: полисемия не определена — нужны либо инвариант «одно определение на корпус» + детектор конфликтов, либо модель скоупа.
- SUBJ-005: любой hunk, затрагивающий definition-span или идентичность термина, — `review`, никогда не `safe`, исключён из паттернов Tier 3.

**Human-Centric Designer**
- SUBJ-001: снимается требование рендер-хука; остаётся запрет синтаксиса, совпадающего с bold/italic.
- SUBJ-006: разметка в теле документов необратима для человека (отличить терминную `_x_` от авторского курсива машинно нельзя) — цена выхода неочевидна в момент принятия.
- SUBJ-008: нужна метрика доли случаев, когда агент ошибся в классе вхождения (термин vs выделение vs код) — единственный прямой показатель нового класса ошибок.

**Operations Engineer**
- SUBJ-006: baseline метрик снимается **до** любых изменений, иначе сравнение невозможно.
- SUBJ-006: до фазы B обязателен замер, сколько токенов/шагов агенты реально тратят на работу с глоссарием сейчас; без него фаза B — решение без проблемы.
- SUBJ-006: `docs/ru/` (17 файлов) остаётся неразмеченным при приостановленной RU-синхронизации → полнота usage-sites ограничена.

## Open Questions

1. Идентичность термина для морфологии и словоформ: lemma-based (нужен инструмент), явный список словоформ, или exact-match (низкий recall)?
2. Полисемия допустима (разные определения в разных документах) или инвариант «одно определение на корпус»?
3. Кто целевой потребитель lookup — агент в сессии, человек-ревьюер, или оба? Требования к provenance и полноте ответа разные.
4. Каков текущий измеренный бюджет агентов на работу с глоссарием? Без цифры нельзя обосновать фазу B.
5. Какова полнота корпуса по usage-sites, если `docs/ru/` остаётся вне разметки?

## Итоговый статус

**Conditionally resolved.** Статусы всех ролей: `concerns`, блоков нет. Принято: реестр как производный read-only индекс (фаза A), глоссарий остаётся авторитетом. Отклонено: реестр как источник истины, синтаксис `__`/`_`, замена чтения глоссария lookup'ом. Отложено: разметка сайтов использования (фаза B) до решения оператора по пункту 7 и замера по пункту 2.

Применение каких-либо правок к проектным документам по итогам сессии не выполняется: требуется отдельное одобрение оператора (AGENTS.md §5.1, шаг 5 Approve).
