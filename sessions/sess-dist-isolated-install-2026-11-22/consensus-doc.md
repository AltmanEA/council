## Authoritative harness fact (operator-provided, OpenCode V2 docs)

Skill discovery sources are extensible via `"skills": ["./.council/skills"]` in any
discovered `opencode.json(c)`; arrays merge across configs. `.council/.agents/skills`
is NOT auto-discovered. Root `AGENTS.md` cannot move. This eliminated symlinks from
every proposal (Ops dropped the S1+symlinks position; RSS rebutted it; Architect and
HC dropped stub layers).

## Decision

Adopt **S4: full relocation under `.council/`, zero symlinks, dual manifests,
manifest-first resolution, standalone migration script.**

### 1. Physical layout (SUBJ-001, SUBJ-005) — AGREED

Host root contains ONLY these Council wiring files:
- `AGENTS.md` (template-derived; thin, points into `.council/`) — harness constraint
- `opencode.json(c)` fragment declaring `"skills": ["./.council/skills"]` and agent
  declarations — harness constraint
- `docs-manifest.yaml` (host-owned, generated) — host tooling entry point
- `.gitignore` additions (managed block)

Everything Council-owned installs flat under `.council/` (no extra `council/` nesting
level; majority over Architect's `.council/council/`):
```
.council/
├── docs/en/<core-docs>/        # documentation-rules, documenter-service,
│                               # translation-project, protocol-core, glossary
├── docs-manifest.yaml          # core manifest (generated, core-only corpus)
├── tools/                      # check_all.py, gen_manifest.py, docmeta.py, hooks/...
├── skills/                     # Documentation Worker skill et al. (config-registered)
├── vendor/techdoc-translator/
├── defaults/translation.lock
├── CHANGELOGS/                 # core-doc seed changelogs
├── fallback/
├── version.lock, core-manifest.txt, update.sh
└── backup-<ts>/                # update backups (gitignored)
```

### 2. Manifests (SUBJ-002) — AGREED: dual manifests

- `.council/docs-manifest.yaml` — core corpus only, generated by
  `gen_manifest.py --root .council` (Architect + RSS; RSS's isolation argument: host
  corruption of the root manifest must never cascade into core toolchain).
- Root `docs-manifest.yaml` — host corpus only, as today.
- **Rejected:** single root manifest with `origin:` field (TOCTOU/confusion risk;
  gen_manifest walks two trees).
- Rejected as unnecessary: RSS's `cross-ref-index.yaml` (OP-2 simplicity; cross-root
  validation lives in check_all instead).

### 3. Cross-root links (SUBJ-003) — AGREED (Architect design)

Host docs reference core docs by abstract canonical path `docs/en/<id>/index.md`;
`check_all.py --core-root .council --host-root .` resolves against both roots and
validates registration in either manifest. No stub files inside host `docs/`
(HC finding, accepted by all; Architect withdrew the `docs/framework/` stub layer).
Core doc frontmatter `changelog-path` resolves relative to the doc's own core root
(`CHANGELOGS/...` → `.council/CHANGELOGS/...`) at tool runtime.

### 4. Tools (SUBJ-008) — AGREED with scoped reduction

- All tools move under `.council/tools/`; gain `--root` (default: auto-detect via
  `SCRIPT_DIR` parent) and `check_all.py` gains `--core-root`/`--host-root`.
- Invoked via thin root wrappers OR direct path `.council/tools/...`; pre-commit hook
  resolves `check_all.py` location-relative from `BASH_SOURCE` (Ops),
  `core.hooksPath=.council/tools/hooks` recommended.
- Prose contracts (`tools/README.md`, `dist/README.md`, `RUNBOOK.md`) updated in the
  same changeset (AGENTS.md §1.7).
- **Scope reduction (HC, accepted):** phase 1 = `check_all.py`, `gen_manifest.py`,
  `docmeta.py`; defer `bump_version.py`, `check_parity.py`, `translation_status.py`
  re-pathing to a follow-up release.

### 5. Update / backup / rollback (SUBJ-004) — AGREED

- `core-manifest.txt` entries become `.council/<path>`; `update.sh` keeps
  `dst="$f"` (manifest owns the path) — Ops confirmed minimal loop change.
- **MF-3 orphan removal (`old_manifest − new_manifest`) is release-blocking**
  (all four roles; prose↔code divergence per §1.7).
- Backup lives in `.council/backup-<ts>/` storing core-root-relative paths; restore is
  the single fixed command `cp -R .council/backup-<ts>/* .council/`, printed by
  `update.sh` at completion and stored in `restore-instructions.txt` per backup (RSS).
- Pre-flight checks (RSS): `.council/` exists and is not a symlink; version.lock and
  core manifest parseable; no symlinks in backup parents; disk-space check before
  partial update; git-clean tree required for migration.

### 6. Migration from flat v0.1.0 (SUBJ-007) — REMOVED FROM SCOPE

Operator decision 2026-11-22: no installed hosts exist; `ai-tutor` will be installed
fresh. `dist/migrate.sh` is dropped entirely; the design is archived in this document
(standalone git-safe script, dry-run + confirmation) should migration ever be needed.

### 7. Symlinks — AGREED: prohibited

No symlinks anywhere in installer/updater wiring (RSS attack-surface analysis:
root symlinks → Council tools operating on attacker-chosen files; harness fact removed
the only functional need). Tools must not follow symlinks out of their roots
(reject during backup/restore path checks).

## Operator decisions (RESOLVED 2026-11-22 — operator replied "as recommended")

**OD-1: `.council/` git tracking → RESOLVED: tracked, with managed gitignore block.**
Track `.council/` in the host repo (HC position, OP-3 audit trail via `git diff`);
installer-managed `.gitignore` block always excludes `.council/backup-*/`,
`.council/**/__pycache__/`, `.council/telemetry/**/*.jsonl`,
`**/techdoc-translator/.env`. Hosts preferring ignore-noise may gitignore
`.council/` entirely — documented option in RUNBOOK.

**OD-2: release shape → RESOLVED: phased.**
v1.0.0 blocking set: `check_all.py`, `gen_manifest.py`, `docmeta.py` (+ `update.sh`
MF-3 fix, `install.sh`, `build.sh`, hooks). Deferred set (`bump_version.py`,
`check_parity.py`, `translation_status.py`, `classify_bump.py`) ships under
`.council/tools/` with explicit pending markers + clear `--root` error messages,
re-pathed in v1.0.x. Deferred tools are not invoked by hooks/audit until done.

**OD-3: `selector.md` → RESOLVED: option B with fallback to A.**
Preferred: selector definition under `.council/agents/`, declared via root
`opencode.jsonc`; verify agent-definition loading from `.council/` works in current
OpenCode V2 before implementation; if unsupported, fall back to root
`.opencode/agents/selector.md` (option A). Decision gate: early spike in the
implementation session.

**MIGRATION: REMOVED FROM SCOPE (operator decision 2026-11-22).** No installed
hosts exist; `ai-tutor` will be installed fresh. `dist/migrate.sh` is dropped;
`test-dry-run.sh` does not test migration; RUNBOOK has no migration section.
Migration, if ever needed, goes to a future session.
