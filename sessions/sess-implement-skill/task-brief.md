# Task Brief — Сессия sess-implement-skill
Дата: 2026-11-15
Режим: Subagent Fallback (fallback/index.md v0.6.0)
Оператор: человек (role selection: base set, 4 Core роли)

## Goal

Спроектировать и добавить новый скилл **«Реализация программных элементов проекта»** (implementation skill),
который вызывается, когда требуется написать код для проекта Council.

## Требуемый процесс (предложение оператора)

Скилл оркестрирует цикл субагентов:

1. **Субагент написания тестов** — пишет тесты по постановке задачи.
2. **Субагент написания кода** — пишет реализацию.
3. **Субагент выполнения тестов** — запускает тесты, собирает вывод.
4. **Субагент анализа результатов** — анализирует прогон, выносит вердикт (pass/fail, причины, гипотезы).

Основной агент (носитель скилла) получает результаты анализа; если цель не достигнута —
корректирует/уточняет промты и перезапускает цикл. После **трёх неудачных прогонов — эскалация к оператору**.

Для каждой фазы цикла должны быть прописаны соответствующие роли (role prompts).

## Контекст и ограничения

- Скилл — implementation file (см. AGENTS.md §1.6), размещается в `.agents/skills/<name>/SKILL.md`,
  вне контроля Documenter; правила записи документации (§2 Write Rule) его не касаются, но не нарушаются.
- Модель субагентов: локальная (по решению оператора — general subagent с freetoken/Qwen3.6-35B-A3B-NVFP4).
- Проект сейчас в фазе Specification→MVP: разрешена реализация Documenter MVP (Tier 0–1) и `tools/` (ADR-011);
  Tier 2+ dormant (ADR-013). Скилл не должен обходить эти ограничения и запрет на council.*/documenter.* MCP.
- Harness: OpenCode. Субагенты запускаются через инструмент subagent (agent=general). Таймаутов между
  фазами нет; субагенты работают в фоновом режиме, основной агент жидёт результатов.
- Тесты: репозиторий содержит `tests/` (implementation file). Скилл должен определить, где живут тесты,
  как запускаются (pytest/CLI), и какие артефакты цикла сохраняются.

## Subject List (канонический)

- SUBJ-001: Структура и активация скилла (имя, описание-триггер, расположение, фронтматтер, когда вызывается / не вызывается)
- SUBJ-002: Пайплайн субагентов и определения ролей (4 роли цикла: Test Author, Code Author, Test Runner, Analyst — контракты входов/выходов)
- SUBJ-003: Внешний цикл основного агента: приём анализа, политика уточнения промтов, критерии «цель достигнута»
- SUBJ-004: Условия остановки и эскалации (лимит 3 прогона, что эскалируется, формат эскалации оператору)
- SUBJ-005: Взаимодействие с governance проекта (Write Rule, separation docs/code, ADR-011/013, запрет MCP, границы «что можно программировать»)
- SUBJ-006: Артефакты и окружение цикла (где тесты, как запуск, рабочие файлы цикла, воспроизводимость, риск порчи репозитория субагентами)

## Output limits

Каждый_review ≤ 200 строк, структура — по fallback/index.md (§Output Structure).

## Constraints / Risks

- Субагенты с локальной моделью могут быть слабее: промты ролей должны быть максимально конкретны.
- Риск: субагент написания кода ломает существующий код / правит не свои файлы.
- Риск: «зацикливание» без реальной коррекции промтов; риск самообмана Analyst (pass при формальном green).
