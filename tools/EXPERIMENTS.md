# Журнал экспериментов: локальный переводчик (`tools/local_translate.py`)

Status: active
Last Modified: 2026-11-10

Операционный документ (вне контроля Documenter, см. AGENTS.md §1.6).
Хранит историю экспериментов над качеством перевода и решения по настройке переводчика.

---

## 1. Назначение

Журнал фиксирует: гипотезу → условия эксперимента → измеримые результаты → вывод/решение.
Каждый эксперимент получает идентификатор `E-NNN`. Новые записи добавляются в конец раздела
«Реестр экспериментов». Записи не редактируются задним числом — уточнения добавляются
отдельным полем «Пост-фактум».

## 2. Методология сравнения

**Принцип одинаковых условий:** сравниваются только модели. Пайплайн неизменен для всех
бэкендов: разбиение на абзацы → поиск терминов глоссария в блоке → глоссарий-hints в промпте
(только найденные термины) → перевод → post-processing (list markers, paths, known typos,
fuzz-fix терминов, enforce_glossary).

**Вызов:**
```bash
# локально
python3 tools/local_translate.py en ru docs/en/glossary/index.md < in.md > out.md
# облако
TRANSLATE_BACKEND=cloud python3 tools/local_translate.py en ru docs/en/glossary/index.md < in.md > out.md
```

**Модели:**

| Роль | Модель | Как задаётся |
|---|---|---|
| Локальная | `kaelri/hy-mt2:7b` (Ollama, localhost:11434) | `OLLAMA_MODEL` |
| Облачная | `qwen3.6-35b-a3b-noreason` (api.neuraldeep.ru, OpenAI-compatible) | `CLOUD_MODEL`, ключ из `~/.config/opencode/opencode.json` или `NEURALDEEP_API_KEY` |

Важно: для облака используется вариант `-noreason` — обычный `qwen3.6-35b-a3b` пишет
рассуждения в `content` и засоряет перевод.

**Метрики:**
1. **Искажённые токены** — мусорные слова, не пойманные пост-обработкой (считаются вручную по фрагменту).
2. **Фактические искажения** — изменённые числа, подмена терминов, потеря смысла.
3. **post-fix вызовы фиксера** — счётчик `[fix]/[fuzz-fix]/[path-fix]` в stderr-логе (нижняя граница дефектов: ловятся только известные опечатки и термины глоссария).
4. **linecount-fallbacks** — сколько блоков модель перевела с нарушением числа строк.
5. **Структурные артефакты** — потерянные маркеры списков, эхо-префиксы (`Translation:`, `===`), теги.
6. **Время/надёжность** — wall time, таймауты, ретраи.

**Тестовые материалы:**
- `docs/en/project-concept/index.md` (32 строки, концептуальный стиль)
- `docs/en/protocol-core/index.md` фрагменты (технический стиль: deployment, observability)

## E-001: Локальная модель vs облачная (2026-11-10)

**Гипотеза:** при идентичном пайплайне облачная qwen3.6-35b-a3b-noreason даёт меньше
дефектов, чем локальная kaelri/hy-mt2:7b.

**Условия:** один и тот же вход, одинаковые SYSTEM_PROMPT, глоссарий-hints (только
термины из блока), post-processing; `temperature=0.2`, `top_p=0.95` на обеих сторонах.

**Входы:** project-concept/index.md (целиком), protocol-core фрагмент 66–80 (Operations Engineer).

### Результаты

| Критерий | Локально hy-mt2:7b | Облако qwen3.6-noreason |
|---|---|---|
| Искажённые токены (фрагмент protocol-core) | ~10 (`эксплуц иатации`, `обесожечивая`, `масшерования` ×2, `работоспостобный`, `хараккьами`, `дажь`…) | 0 |
| Фактические искажения (project-concept) | `2026-11-04`→`2026-11-00`; `A framework`→`Платформа`; `by different roles`→`разными специалистами`; `start minimal`→`Функции…минимального набора` | не обнаружены |
| Маркеры списков `1.` / `-` | теряются, чинит `restore_list_marker` | сохраняет сама |
| post-fix вызовы фиксера (фрагмент) | 1 | 0 |
| linecount-fallbacks | бывают | бывают реже |
| Структурные артефакты | эхо `**Translation:**` (фильтруется) | эхо `===` (добавлена очистка); у reasoning-версии — текст рассуждений в content |
| Скорость | быстрее (нет сети) | медленнее (сеть), стабильно, без таймаутов |

### Вывод

Облако qwen3.6 однозначно выигрывает, в т.ч. по критичному для документации критерию —
фактической точности (локальная 7B тихо меняет числа и подменяет термины).
Локальная модель пригодна только как офлайн-фолбэк для черновых переводов.

**Решение:** основной бэкенд — облако (`TRANSLATE_BACKEND=cloud` по умолчанию для
проектных переводов); локальный режим сохраняется как fallback без сети.

**Изменения в коде по итогам:** добавлен cloud-бэкенд (`call_model` → `_call_cloud`,
OpenAI-compatible chat/completions), очистка эхо-`===`, ключ читается из конфига OpenCode.

## E-002: Bake-off облачных базовых моделей (2026-11-10)

**Гипотеза:** среди подключённых облачных моделей есть вариант лучше текущей базовой
`qwen3.6-35b-a3b-noreason` (например, RU-специфичная итерация или новее семейство).

**Условия:** 5 моделей × 3 входа, один пайплайн, `temperature=0.2`:
- Модели: `qwen3.6-35b-a3b-noreason`, `qwen3.6-35b-a3b` (reasoning), `qwen3.6-fp8-noreason`,
  `qwen3.8-27b-noreason`, `qwen3.8-flash-next-ru-noreason`.
- Входы: T1 = project-concept целиком (32 стр., концептуальный); T2 = protocol-core 66–80
  (Ops Engineer, технич.); T3 = protocol-core 159–171 (таблица маршрутизации, enum'ы, code-токены).
- Сырьё и выходы: `/tmp/opencode/bakeoff/`.

### Результаты

| Модель | T1 | T2 | T3 | Время (T1/T2/T3) | Дефекты |
|---|---|---|---|---|---|
| qwen3.6-35b-a3b-noreason | 0 fail | 0 fail | 1 linecount-fb | 4/3/7 c | «замечания»-contamination (см. ниже) |
| qwen3.6-35b-a3b (reasoning) | 4 linecount-fb | 4 linecount-fb | 1 FAIL, **протёкшие рассуждения в content** («Wait, the input has backticks…») | 224/215/350 c | reasoning непригодна как есть |
| qwen3.6-fp8-noreason | 0 fail | 0 fail | 1 linecount-fb | 13/11/15 c | как у базовой; стиль идентичен; в T3 добавил лишний `**bold` |
| qwen3.8-27b-noreason | 5 FAIL (метаданные непереведены, L2–6) | 0 fail | 1 FAIL | 12/13/12 c | **сломан вывод** (см. ниже); в T1 «различными ролями», «разнобоком взгляде» — чисто |
| qwen3.8-flash-next-ru-noreason | 5 FAIL (то же) | 0 fail | 1 FAIL | 15/8/9 c | тот же сбой метаданных; RU-стиль местами естественнее («решения» вместо канцелярского «проекты»), но: «фазы Фаза_state», «Ключевой Роли» — порча code-токенов и неверный падеж |

### Ключевые находки

1. **qwen3.8 (обе вариации) «зависают» на YAML-метаданных**: строки `Version:`…`changelog-path:`
   возвращаются untranslated (FAIL), модель их копирует. В T2/T3 метаданных нет — в тех
   прогонах чисто. Т.е. сбой специфичен для заголовков документов.
2. **Reasoning-версия qwen3.6 непригодна**: рассуждения протекают в `content` (43 совпадения
   с «Wait/Let's» в T3), время ×30–50. Подтверждён вывод E-001 про `-noreason`.
3. **fp8 — качество идентично базовой bf16** (совпадение формулировок ~1-в-1), но медленнее
   в 2–4 раза в этих замерах. Выигрыша нет.
4. **RU-специфичная flash-next-ru НЕ превзошла** базовую: лучше отдельных формулировок,
   но добавила новые типы ошибок (порча `phase_state` → `Фаза_state`, неверные падежи терминов).
5. **Contamination глоссарием (все модели, системно):** в T3 «each `ConsensusVerdict.outcome`
   **value**» переведено всеми как «**замечания**» — из-за hints `Concerns → Замечания` /
   `Finding → Вывод` в блоке. A/B-проверка без глоссария: «каждое значение … сопоставляется» —
   корректно. Т.е. hints влияют на НЕсовпадающие слова. Это дефект промпт-формата → тема E-00x промпт-серии.

### Промежуточные итоги (bake-off)

- **Базовая модель остаётся `qwen3.6-35b-a3b-noreason`** — единственный участник без сбоев
  вывода, самый быстрый, качество эталонное. Замены в текущем каталоге нет.
- Все облачные noreason-модели дают 0 орфографических дефектов и 0 фактических искажений —
  различия только в стиле и устойчивости к краям (метаданные, code-токены, таблицы).
- Открытый дефект пайплайна: contamination от глоссарий-hints (находка 5) — важнее выбора модели.

**Решение:** зафиксировать `qwen3.6-35b-a3b-noreason` как базовую; эксперименты направить
на параметры запроса и формат hints, а не на поиск модели. (Дополнено пост-фактумом ниже.)

### Пост-фактум (2026-11-10): локальная NVFP4-версия той же архитектуры

По запросу оператора прогнаны те же T1–T3 на `Qwen3.6-35B-A3B-NVFP4` (локальный
OpenAI-compatible сервер `http://127.0.0.1:8000/v1`, vLLM-подобный), тот же пайплайн:

| Критерий | NVFP4 локально | Облако qwen3.6-noreason |
|---|---|---|
| FAIL / linecount-fallbacks | 0 / 0 (T1,T2); T3: 1 FAIL — строка-разделитель таблицы вернулась как есть (статистический артефакт: перевод совпал с исходником, что для `|---|` корректно) | 0 / 0; T3: 1 linecount-fb |
| Метаданные T1 | переведены корректно (Версия/Статус/Путь…) | то же |
| Орфография / факты | 0 дефектов | 0 дефектов |
| Contamination T3 («value»→«замечания») | **не проявилась**: «каждому значению … сопоставлен» — верно | проявилась |
| Стиль | чуть более «гроссный»: mid-sentence капитализация терминов (Артефакта, Эскалации, Резолюции) | строчные формы, ближе к норме |
| Время (T1/T2/T3) | 151/103/102 c | 4/3/7 c |

**Вывод пост-фактума:** NVFP4-квантизация того же 35B-A3B качества, что и облачная базовая —
полноценный локальный кандидат (в отличие от hy-mt2 из E-001). Отличается: ×20–25 медленнее
и более «тяжёлой» капитализацией терминов. Contamination в T3 у облачной версии при
temperature=0.2 может быть sampling-варианцией — требует проверки на повторных прогонах (входит в E-003).
**Обновлённое решение:** облако `qwen3.6-35b-a3b-noreason` — основной бэкенд (скорость);
`Qwen3.6-35B-A3B-NVFP4` @ 127.0.0.1:8000 — штатный офлайн-фолбэк вместо hy-mt2.

### Пост-фактум 2 (2026-11-10): NVFP4 в noreason-режиме

Обнаружено: локальный сервер (vLLM) по умолчанию держит Qwen3.6 в thinking-режиме —
предыдущий NVFP4-прогон генерировал скрытый `reasoning_content` (отсюда 100–150 с).
Сервер принимает `chat_template_kwargs={"enable_thinking":false}` → перевод в noreason.
В скрипт добавлен проброс через env `CLOUD_CHAT_KWARGS`.

Прогон T1–T3, `CLOUD_CHAT_KWARGS='{"enable_thinking":false}'`:

| Критерий | NVFP4 thinking (было) | NVFP4 noreason (стало) | Облако 3.6-noreason |
|---|---|---|---|
| Время T1/T2/T3 | 151/103/102 c | **9/5/6 c** | 4/3/7 c |
| Дефекты вывода | 0 / 0 / 1 ложный FAIL | **0 / 0 / 0** (в т.ч. разделитель таблицы переведён) | 0 / 0 / 1 linecount-fb |
| Орфография / факты / метаданные | чисто | чисто | чисто |
| Contamination T3 | не проявилась | не проявилась | нестабильно: из 3 прогонов «замечания» в 2 |
| Стиль T2 | капитализация терминов | строчные формы (как облако), «как проекты ведут себя» — тот же канцеляризм, что у облака | идентично |

**Выводы:**
1. Thinking-режим был причиной всей задержки локальной модели; noreason-режим делает NVFP4
   сопоставимым с облаком по скорости (×1.5–2 медленнее, при локальном железе это приемлемо).
2. Качество NVFP4-noreason идентично облачному noreason, включая стилистику; thinking-версия
   отличалась более «гроссным» стилем (капитализация терминов).
3. Повторные прогоны облака T3 подтвердили: contamination — sampling-вариация
   (≈2/3 воспроизводимости при temp=0.2), а не детерминированный сбой формата hints.
   У NVFP4-noreason в 2 прогонах — 0 случаев.

**Итоговое решение по фазе выбора модели:**
- Основной офлайн-бэкенд: `Qwen3.6-35B-A3B-NVFP4` + `CLOUD_CHAT_KWARGS='{"enable_thinking":false}'`
  (независимость от сети, скорость ~6 c/тест, качество на уровне облака).
- Облако `qwen3.6-35b-a3b-noreason` — равноценная альтернатива / фолбэк локального сервера.
- Мысль о преимуществе облака по скорости из пост-фактума 1 **снята**: оно держалось только
  за счёт noreason-режима на сервере.

## E-003: Формат глоссарий-hints против contamination (2026-11-10)

**Гипотеза:** contamination («value»→«замечания» из-за hints `Concerns → Замечания`)
устраняется переформулировкой блока hints.

**Условия:** локальный NVFP4 + noreason, temp=0.2. Ловушка — T3-L1 (содержит «value»
рядом с термином `Escalation reason`). 4 варианта хедера hints × 3 повтора:
- `verbose` (бывший дефолт): «Glossary (use exactly these term translations):»
- `strict`: «Apply a translation ONLY where the exact English term itself occurs;
  **never use these Russian words for other words**:»
- `plain`: «The following words must be translated as shown:»
- `none`: глоссарий не передаётся (контроль).

Регрессия: полные T1–T3 на каждый style.

### Результаты

| Хедер hints | Contamination на ловушке (3 прогона) | Регрессия T1–T3 |
|---|---|---|
| verbose | 1/3 | чисто (1 ложный FAIL-разделитель) |
| strict (негативная директива) | **3/3** | чисто |
| plain | **0/3** | чисто |
| none (без глоссария) | 0/3 | — |

### Выводы

1. **Негативные директивы контрпродуктивны** («never use these words…» → 3/3): упоминание
   запретного усиливает его вероятность (эффект «не думай о белом медведе»). Использовать запрещать.
2. **`plain` — победа:** короткая позитивная формулировка «must be translated as shown»,
   0/3 contamination. Внедрён как дефолт (`TRANSLATE_HINT_STYLE`, значения: plain|verbose|strict).
3. **Терминологическая дисциплина не пострадала:** канонические эквиваленты
   (Причина эскалации, Формирование резолюции, раунд обсуждения) присутствуют во всех
   трёх стилях регрессии — hints продолжают работать.
4. Контроль `none` подтверждает: источник contamination — сам факт передачи пар
   «термин→перевод» для совпавших терминов; полностью исключить hints нельзя (иначе
   ломаются канонические термины), но `plain`-формулировка сводит побочный эффект к нулю
   в выборке.

**Решение:** дефолт хедера — `plain`; `strict` помечен в коде как «DO NOT USE».

## E-004: Температура 0.2 / 0.4 / 0.5 (2026-11-10)

**Гипотеза:** temp 0.4–0.5 даёт более естественный RU-стиль без потери точности.

**Условия:** локальный NVFP4 + noreason, plain-hints (после E-003); T2 × 2 повтора +
ловушка TRAP × 2 повтора на каждую температуру (6 конфигураций, 12 прогонов).

### Результаты

| Конфиг | Дефекты (лог/ручная) | Contamination TRAP | Стабильность |
|---|---|---|---|
| temp 0.2 | 0 | 0/2 | базовая |
| temp 0.4 | 0 | 0/2 | 2 строки разошлись с 0.2 |
| temp 0.5 | 0 | 0/2 | 6 из 15 строк разошлись с 0.2 |

Стилистические наблюдения (T2, ручной просмотр):
- при 0.4–0.5 стабильно «мыслит категориями» (идиоматичнее, чем «рассуждает с точки зрения»);
- но при 0.5 заметнее кальки: «отправить свой заказ» (vs «оформить заказ» при 0.2),
  «шаблон развертывания» (vs «схема»), «состояние интеграции» (vs «работоспособность»);
- согласование прилагательных в скобках («сине-зелёный/синее-зелёное/канареечный») хромает
  при обеих температурах — не связано с temp.

### Вывод

Единого «более естественного» режима нет: 0.4–0.5 выигрывает в отдельных оборотах,
проигрывает в кальках; дефектов не добавляет, но повышает вариативность между прогонами
(6/15 строк расхождение) — воспроизводимость перевода падает. Для проектной документации
воспроизводимость важнее разовых стилистических удач.

**Решение:** temp=0.2 остаётся дефолтом. Заражённости ловушки нет ни при одной температуре
(подтверждает: contamination лечится форматом hints, а не sampling-параметрами — связка с E-003).

## E-005: Метаданные заголовка — модель vs пропуск (2026-11-10)

**Гипотеза:** строки метаданных (`Version:`, `Status:`, `Last Modified:`, `Abstraction:`,
`changelog-path:`) выгоднее не отдавать модели.

**Проверка:** прогон T1 (project-concept) с пропуском метаданных (NVFP4-noreason, plain-hints)
vs прежний режим перевода модели.

### Результаты

| Аспект | Модель переводит метаданные | Пропуск (новый дефолт) |
|---|---|---|
| Клави/структура | модель переводит ключи (`Версия:`, `Статус:`) — рассогласование с парсером Documenter | ключи и значения интактны |
| Риск искажения значений | реальный случай из E-001: дата `2026-11-04`→`2026-11-00` (hy-mt2); qwen-модели даты сохраняли | нулевой |
| Конвенция проекта | противоречит: существующие `docs/ru/*/index-RU.md` держат метаданные на английском | соответствует |
| Тело документа | без изменений | без изменений (2 стилистические вариации — sampling-шум) |

Дополнительно: этот же механизм объясняет «FAIL» qwen3.8-27b на T1 в E-002 — модель
возвращала метаданные untranslated; теперь это эталонное поведение, а не дефект.

### Вывод и решение

Метаданные не переводятся (дефолт). Реализация: `is_metadata_line()` + флаг в
`needs_skip()`; возврат к прежнему поведению — `TRANSLATE_METADATA=1`. Совместимо с
требованием line-parity для RU-выравнивания (§3.3): строки на своих местах.

## E-006: Guard-директива для code-spans (2026-11-10)

**Гипотеза:** директива «не изменять содержимое `backticks`» снижает порчу code-токенов
(в E-002 qwen3.8-flash портила `phase_state` → `Фаза_state`).

**Условия:** T3 (11 уникальных code-токенов: enum'ы, `ConsensusVerdict.outcome`,
`awaiting-operator` и т.п.), NVFP4-noreason, base system prompt vs +codeguard, 2 повтора.
Метрика: доля токенов, сохранившихся посимвольно.

### Результаты

| Конфиг | rep1 | rep2 |
|---|---|---|
| base | 11/11 | 11/11 |
| codeguard | 11/11 | 11/11 |

### Вывод и решение

Базовая модель (NVFP4-noreason) сохраняет code-токены без подсказки — проблема E-002
была специфична для qwen3.8-flash, не для выбранной базовой. Директива **не нужна**;
вариант `TRANSLATE_PROMPT=codeguard` оставлен в коде как инструмент для других моделей
(например, при облачном фолбэке). Дальнейшие эксперименты с формулировками промпта —
только если при смене модели появится измеримый дефект этого класса.

## E-007: Чанкинг «секция вместо абзаца» (2026-11-10)

**Гипотеза:** перевод секции одним блоком повышает единообразие перевода одного термина
в разных абзацах (контекст помогает).

**Условия:** секция «Escalation Protocol» protocol-core (стр. 179–205, термин Escalation
в 6+ позициях), NVFP4-noreason, 2 повтора × 2 варианта (абзацы / единый блок через
`TRANSLATE_FORCE_SECTION=1`). Метрика: множество различных форм термина в выводе.

### Результаты

| Вариант | rep1 | rep2 |
|---|---|---|
| абзацы | {эскалация, эскалации, эскалацию, эскалацией} | идентично rep1 |
| секция | тот же набор форм | идентично rep1 |

### Вывод и решение

Различие форм — это корректные русские падежи (грамматическая норма), а не несогласованность
переводов; состав лемм идентичен в обоих режимах. Секционный чанкинг **не даёт выигрыша**
в консистентности, при этом увеличивает риск line-count расхождений (больше строк в блоке —
дороже fallback) и снижает распараллеливаемость. Абзацный чанкинг остаётся дефолтом;
`TRANSLATE_FORCE_SECTION` оставлен как экспериментальный флаг.

**Ограничение методики:** метрика «различные словоформы» смешивает падежи с несогласованностью;
для будущих проверок сравнивать леммы (нормализация к именительному падежу), а не словоформы.

## E-008: top_p 0.8 vs 0.95 (2026-11-10)

**Гипотеза (слабая):** при temp=0.2 сужение top_p до 0.8 может повысить стабильность.

**Условия:** T2, 2 повтора × 2 значения top_p (реализовано через `TRANSLATE_TOP_P`).
Методика: сравнение «между конфигами» против baseline-шума «между повторами одного конфига».

### Результаты

| Сравнение | Расходящихся строк (из 15) |
|---|---|
| top_p 0.95 rep1 vs rep2 (шум) | 3 |
| top_p 0.80 rep1 vs rep2 (шум) | 5 |
| 0.95 vs 0.80 (rep1↔rep1, rep2↔rep2) | 3 и 3 |

Расхождения — синонимические варианты («настройка/конфигурация автоскейлинга»,
«паттернов/шаблонов», «оформить/отправить заказ»), дефектов нет ни в одном прогоне.

### Вывод

Межконфигурные расхождения не превышают внутриконфигурный sampling-шум → эффект top_p
в диапазоне {0.8; 0.95} при temp=0.2 неотличим от шума. **top_p=0.95 остаётся.**
Параметр `TRANSLATE_TOP_P` оставлен в коде. Закрытие оговорки методики E-007: здесь
сравнение корректно отделяло эффект от шума (в отличие от «сырого» сравнения выводов).

**Backlog фазы 2 закрыт полностью (E-003…E-008).** Следующая фаза (по желанию оператора):
промышленная эксплуатация настроек из таблицы «Промежуточные итоги»; новые эксперименты —
только при смене модели или появлении измеримого дефекта.
