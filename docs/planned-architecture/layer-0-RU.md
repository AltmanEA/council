## Назначение

Детерминированное обеспечение соблюдения всех правил протокола. Нулевые зависимости от фреймворков. Чистые функции Python. Проверяются прямым импортом.

## Контракт интерфейса

```python
def evaluate_consensus(role_statuses: list[dict]) -> ConsensusVerdict
def validate_subject_references(subjects: list[dict], text: str) -> list[ValidationResult]
def extract_role_status(review_text: str) -> RoleStatus | InvalidFormat
def check_justification_format(finding: dict) -> FormatValid | FormatInvalid
```

### extract_role_status() — Подпись и тип возврата

```python
def extract_role_status(review_text: str) -> RoleStatus | InvalidFormat
```

В случае успеха возвращает `RoleStatus` с `extraction = parsed`, или артефакт `InvalidFormat` при ошибке разбора. Потребители НЕ ДОЛЖНЫ использовать какое-либо значение статуса по умолчанию для ответа с недействительным форматом; см. §Политика InvalidFormat для обработки сессии. Слой 1 передаёт этот тип возврата непосредственно в конвейер вычисления консенсуса.

### InvalidFormat

Создаётся функцией Layer 0 `extract_role_status()`, когда текст обзора не может быть разобран (перечисление статуса не опознаётся, отсутствуют обязательные поля). Потребители НЕ ДОЛЖНЫ выводить значение статуса по умолчанию; сессия переходит в состояние `blocked-escalation` с `escalation_reason = information-gap`.

| Поле | Тип | Обязательно | Правило |
|-------|------|----------|------|
| `error_code` | string | да | Всегда `invalid-format` |
| `raw_text_hash` | string | да | `sha256` исходного текста обзора, предоставленного ролью |
| `parse_attempted` | boolean | да | `true` — указывает, что попытка была, но завершилась ошибкой |
| `role_id` | string \| null | нет | Если известно из контекста конверта; отсутствует, если сам обзор некорректен |
| `session_id` | string \| null | нет | Если известно из контекста конверта; отсутствует, если сам обзор некорректен |

## Правила границы

- Вызывается только Слоем 1 (выполнение роли). Никогда не доступен напрямую Слоем 2 (поверхностные инструменты). Если Слой 2 требуется поведение протокола, он вызывает через Слой 1.
- На этом слое запрещены импорты фреймворков. Никаких LangChain, LangGraph, FastAPI, зависимостей от SQLite.

## Инварианты (ADR-001: Структурные утверждения + тесты на основе свойств)

Все обеспечиваются явными операторами `assert` и свойствами Hypothesis. Ни одна LLM не участвует в проверке безопасности.

| Инвариант | Описание |
|-----------|-------------|
| Присутствие Core-ролей | Все роли уровня Core активны по умолчанию; исключение требует `locked_roles` + `operator_approval: true` в SessionManifest (service-contract §SessionManifest). Отсутствие Core-роли без одобрения — блокирующая ошибка (PROT.001). |
| Целостность эскалации | Пути эскалации не могут быть удалены или ослаблены никаким параметром |
| Независимость консенсуса | Логика вычисления консенсуса не может быть переопределена конфигурацией сценария |
| Обоснование критических находок | Валидация обоснования критических находок всегда выполняется, независимо от сложности задачи |
| Правило блокировки по уровню серьёзности | Только medium и выше могут способствовать блокировке задачи |
| Структурная проверка позиции | Обнаружение разногласий использует поля позиции, машиночитаемые, а не текстовую интерпретацию |

## Сохранение состояния

Состояние фазы сериализуется в отдельные JSON-файлы в `sessions/<id>/`. Общего состояния между сессиями нет. Только кратковременные задачи — ACID не требуется. Нет SQLite. Нет сериализованных checkpoint-файлов. Plain JSON с отсортированными ключами при записи.
