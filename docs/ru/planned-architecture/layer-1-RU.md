## Назначение

Выполните протокол Совета. Уровень 1 объединяет детерминированную плоскость управления (Модератор) с недетерминированными исполнительными модулями (Агенты Роли и Вспомогательные Агенты). Это единственный уровень, который вызывает Уровень 0.

## Внутренние модули

| Модуль | Ответственность | Может импортировать |
|--------|----------------|------------|
| `orchestrator/` | Фаза конечного автомата, Модератор, консенсус и маршрутизация эскалации | `agents/`, `scenario/`, `persistence/`, Уровень 0 |
| `agents/` | Роль Агенты, Вспомогательные Агенты, `RoleAgentFactory`, `get_model()` | `scenario/`, типы парсеров Уровня 0 |
| `scenario/` | `ScenarioLoader`, проверка сценария | Типы каталога Уровня 0 |
| `persistence/` | Манифест сессии, файлы фазы, атомарные записи | — |

Правила импорта:

- `orchestrator/` может импортировать другие модули; `agents/` НЕ ДОЛЖЕН импортировать `orchestrator/`.
- Только `agents/` может вызывать `get_model()`; `orchestrator/` НЕ ДОЛЖЕН импортировать его напрямую.
- Слой 1 НЕ ДОЛЖЕН импортировать Слой 2.

## Модератор

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию произвольного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения, связанные с фазой и консенсусом, являются детерминированными функциями проверенных выводов ролей; ни одна модель не участвует в управлении потоком выполнения или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Политика нулевых значений по умолчанию (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область действия |
|-----------|---------|-------|
| температура | 0.1 | Задача: обзоры |
| top_p | 0.9 | Задача: обзоры |
| frequency_penalty | 0.0 | нейтральный (явно установлен, никогда не выводится) |

Список разрешённых значений по умолчанию управляется централизованно в файле `defaults/policy.yaml`. Внесение изменений требует оформления pull request с обоснованием. Пересмотр осуществляется ежеквартально.

### Хук валидации контракта

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит обязательные разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никаких несанкционированных инструкций, добавленных за пределы определения роли и контекста сценария

### Отслеживаемость манифеста сессии

Каждая запись сессии включает раздел `"role_agent_config"`, в котором перечислены точные параметры, использованные для каждой активной роли, с возможностью проследить их от конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### Правило отсутствия модификации запроса

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты до фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничивается только акцентированием внимания/внедрением контекста — подмена поведения запрещена.

## Вспомогательные агенты

Вспомогательные агенты — это рабочие LLM без роли, вызываемые средой выполнения для выполнения вспомогательных задач. Документатор использует Документатора как первый экземпляр: Документатор вызывает Порт исполнения первого уровня, который создает рабочего через `agents/`. Вспомогательные агенты никогда не участвуют в Консенсусе, никогда не голосуют и никогда не продвигают Фаза.

## Загрузчик сценариев

Загружает и проверяет корректность файлов конфигурации **Сценарий**. Отображает объявления **problem_type** на наборы **Роль** по умолчанию. Предварительно проверяет, что активированные **Роль** существуют в каталоге, прежде чем передавать их в RoleAgentFactory. Соответствие **Сценарий** является задачей уровня 1; уровень 2 передает только **Задача** и идентификатор **Сценарий**.

## Абстракция модели

Единая точка входа `get_model()` абстрагирует детали провайдера. В MVP используется один провайдер; для его замены достаточно изменить только эту функцию. Точка входа принадлежит модулю `agents/`; модуль `orchestrator/` никогда не импортирует её. Парсер структурированного вывода преобразует ответы LLM во валидированное промежуточное представление перед передачей в Layer 0.

## Управление фазой

Только `orchestrator/` продвигает фазу. Каждый переход является детерминированной функцией проверенных артефактов. Состояния фаз, защитные механизмы, маршрутизация эскалации и механики сохранения сессии указаны в спецификации «Среда исполнения и жизненный цикл сессии».

## Путь миграции

Если оркестрация выходит за пределы уровня 1, извлеките ядро оркестрации за публичным интерфейсом уровня 1 (вариант B). Границы слоёв и правило уровня 0 остаются неизменными.
