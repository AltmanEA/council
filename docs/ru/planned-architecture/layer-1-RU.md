## Назначение

Выполнять протокол Консилиума. Слой 1 сочетает детерминированную управляющую плоскость (Модератор) с недетерминированными единицами исполнения (Ролевые агенты и Вспомогательные агенты). Это единственный слой, который обращается к Слой 0.

## Внутренние модули

| Модуль | Ответственность | Может импортировать |
|--------|----------------|------------|
| `orchestrator/` | Машина состояний фаз, Модератор, маршрутизация консенсуса и эскалации | `agents/`, `scenario/`, `persistence/`, Слой 0 |
| `agents/` | Ролевые агенты, Вспомогательные агенты, `RoleAgentFactory`, `get_model()` | `scenario/`, типы парсера Слой 0 |
| `scenario/` | `ScenarioLoader`, валидация сценария | типы каталога Слой 0 |
| `persistence/` | Манифест сессии, файлы фаз, атомарные записи | — |

Правила импорта:

- `orchestrator/` может импортировать остальные модули; `agents/` НЕ ДОЛЖЕН импортировать `orchestrator/`.
- Только `agents/` может вызывать `get_model()`; `orchestrator/` НЕ ДОЛЖЕН импортировать его напрямую.
- Слой 1 НЕ ДОЛЖЕН импортировать Слой 2.

## Модератор

Модератор — детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через Слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не принимает решений и не содержит вызовов LLM. Решения по фазам и консенсусу — детерминированные функции проверенных выводов ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов из проверенной конфигурации сценария.

### Политика нулевых скрытых значений по умолчанию (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного значения, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые значения по умолчанию появляются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|----------|----------------------|-------------------|
| temperature | 0.1 | проверки аналитических задач |
| top_p | 0.9 | проверки аналитических задач |
| frequency_penalty | 0.0 | нейтральный (явно установлен, никогда не выводится) |

Список разрешённых значений по умолчанию управляется централизованно в `defaults/policy.yaml`. Расширение требует PR с обоснованием. Пересматривается ежеквартально.

### Хук валидации контракта

После создания, но перед добавлением в очередь, проверить:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон промпта содержит обязательные разделы (perspective, responsibilities, output structure reminder)
- За пределы определения роли и контекста сценария не добавлены несанкционированные инструкции

### Прослеживаемость манифеста сессии

Каждая запись сессии включает раздел `"role_agent_config"` со списком точных параметров, использованных для каждой активной роли, прослеживаемый обратно до: конфигурация сценария → разрешение фабрикой → фактическая инстанциация агента.

### Правило неизменности промпта

Фабрика внедряет контекст, специфичный для сценария (scope задачи, название сценария, результаты пре-фазы), но НЕ модифицирует базовый шаблон промпта роли. Кастомизация промпта ограничена только усилением/внедрением контекста — подмена поведения запрещена.

## Вспомогательные агенты

Вспомогательные агенты — это агенты LLM, не относящиеся к ролям, вызываемые средой исполнения для поддерживающих задач. Documentation Worker, используемая Documenter, — первый экземпляр: Documenter вызывает порт исполнения Слой 1, который инстанцирует рабочего через `agents/`. Вспомогательные агенты никогда не участвуют в консенсусе, никогда не голосуют и никогда не продвигают фазу.

## ScenarioLoader

Загружает и валидирует файлы конфигурации сценария. Отображает объявления problem_type на наборы ролей по умолчанию. Предварительно проверяет, что активированные роли существуют в каталоге, перед передачей в RoleAgentFactory. Соотнесение сценариев — задача Слой 1; Слой 2 только передаёт задачу и идентификатор сценария.

## Абстракция модели

Единая точка входа `get_model()` абстрагирует детали провайдера. MVP использует одного провайдера; замена требует изменения только этой функции. Точка входа находится в собственности `agents/`; `orchestrator/` никогда не импортирует её. Парсер структурированного вывода преобразует ответы LLM в проверенное промежуточное представление перед передачей в Слой 0.

## Управление фазами

Только `orchestrator/` продвигает фазу. Каждый переход — детерминированная функция проверенных артефактов. Состояния фаз, защитные проверки, маршрутизация эскалации и механика сохранения сессии указаны в спецификации «Среда исполнения и жизненный цикл сессии».

## Путь миграции

Если оркестрация выйдет за пределы Слой 1, извлечь Orchestration Core за пределы публичного интерфейса Слой 1 (вариант B). Границы слоёв и правило Слой 0 остаются без изменений.
