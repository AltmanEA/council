## Обзор

Council использует три основных слоя плюс вспомогательные сервисы. Зависимости направлены только вниз: ни один слой не импортирует ничего из слоя выше него, а вспомогательные сервисы имеют ограниченный интерфейс вызовов. Модератор не является отдельным слоем — это детерминированная управляющая плоскость внутри слоя 1.

```
Layer 2 ─ External Interfaces / Adapters
          MCP stdio transport · input validation · error localization · operator surface
              │ invoke
              ▼
Layer 1 ─ Execution Runtime
          deterministic Moderator · Role Agents · Auxiliary Agents · ScenarioLoader · persistence
              │
              ▼
Layer 0 ─ Protocol Enforcement
          deterministic consensus · validation rules

Supporting services (outside the layer chain)
          Documenter · JSON persistence

FALLBACK NOTICE — see §Operational Modes
```

## Сводка слоёв

| Слой | Имя | Обязанность | Детерминированность |
|-------|------|----------------|-------------|
| 2 | Внешние интерфейсы / Адаптеры | Транспорт, валидация входящих данных, локализация ошибок, поверхность оператора | Только адаптеры; без LLM |
| 1 | Среда исполнения | Оркестрация фаз, инстанцирование агентов, загрузка сценариев, сохранение сессий | Смешанная: детерминированный Модератор, недетерминированные агенты |
| 0 | Обеспечение протокола | Оценка консенсуса, валидация субъекта, извлечение статуса, формат обоснования | Полностью детерминировано; без LLM |

## Правила зависимостей

- Слой 2 может вызывать слой 1. Он НЕ ДОЛЖЕН вызывать слой 0 напрямую.
- Слой 1 может вызывать слой 0. Слой 0 не вызывает ничего, что находится выше него.
- Слой 1 НЕ ДОЛЖЕН импортировать слой 2. Слой 0 НЕ ДОЛЖЕН импортировать слой 1 или слой 2.
- Слой 2 НЕ ДОЛЖЕН напрямую вызывать LLM. Доступ к LLM ограничен агентами слоя 1 через `get_model()`.
- Модератор детерминирован и находится в слое 1 (`orchestrator/`). Ни один LLM не участвует в управляющем потоке или проверке безопасности.

## Вспомогательные сервисы

Вспомогательные сервисы находятся вне цепочки слоёв. Они могут вызывать Слой 1 и НЕ ДОЛЖНЫ вызывать Слой 2 или Слой 0 напрямую.

| Сервис | Роль | Поверхность вызова |
|---------|------|--------------|
| Documenter | Аудит документации и делегированные записи | Вызывается через поверхность оператора слоя 2; записи с поддержкой LLM используют порт исполнения слоя 1 |
| JSON сохранение | Хранилище состояния сессии (`sessions/<id>/`) | Используется Слой 1 `persistence/`; только локально, не добавляется в коммит |

## Режимы работы

**Режим fallback** — это режим работы, который заменяет основанный на коде Модератор до начала реализации (см. `fallback/index.md`). Он работает через именованные подагенты, запускаемые через этот агентный интерфейс. Сессии в режиме fallback исключены из требований `SessionManifest` (см. `execution-runtime/index.md` §Правило пространства имён) и разделяют с канонической спецификацией только формат артефактов. Модератор, основанный на коде, после реализации заменит fallback как режим по умолчанию для разработки.

## Путь миграции

Если оркестрация превысит возможности слоя 1, извлеките ядро оркестровки за публичным интерфейсом слоя 1. Границы слоёв и правило слоя 0 остаются без изменений.

## Улучшения

Все шесть функциональных улучшений из Архитектуры B интегрированы; ни одно из них не требует изменений границ слоёв. Отложенные элементы — каталог ScenarioLoader, цепочка миграции схемы, классификатор быстрого обзора, Typer CLI, checkpoint/resume, распределённая блокировка — перечислены в консенсусном документе, который привёл к этой редакции, и будут отслеживаться в спецификациях сервисов.

См.: `layer-0.md`, `layer-1.md`, `layer-2.md`, `decisions/index.md`.
