## Обзор

Совет использует три основных слоя, а также вспомогательные сервисы. Зависимости направлены только вниз: ни один слой не импортирует элементы из расположенного выше слоя, а вспомогательные сервисы имеют ограниченный интерфейс вызовов. Модератор не является отдельным слоем — это детерминированная управляющая плоскость внутри первого слоя.

```
Layer 2 ─ External Interfaces / Adapters
          MCP stdio transport · input validation · error localization · точка входа оператора
              │ invoke
              ▼
Layer 1 ─ Execution Runtime
          deterministic Moderator · Role Agents · Auxiliary Agents · ScenarioLoader · persistence
              │
              ▼
Layer 0 ─ Protocol Enforcement
          deterministic consensus · validation rules

Supporting services (outside the layer chain)
          Documenter · JSON persistence

FALLBACK NOTICE — see §Operational Modes
```

## Сводка по слоям

| Слой | Имя | Ответственность | Детерминированность | Перевод:
|-------|------|----------------|-------------|
| 2 | Внешние интерфейсы / Адаптеры | Транспорт, проверка входящих данных, локализация ошибок, интерфейс оператора | Только адаптеры; без LLM |
| 1 | Среда исполнения | Оркестрация фаз, создание агентов, загрузка сценария, сохранение сессии | Смешанная: детерминированный Модератор, недетерминированные агенты |
| 0 | Обеспечение протокола | Оценка консенсуса, проверка объекта обсуждения, извлечение статуса, формат обоснования | Полностью детерминированная; без LLM |

## Правила зависимостей

- Layer 2 может вызывать Layer 1. Он НЕ ДОЛЖЕН вызывать Layer 0 напрямую.
- Layer 1 может вызывать Layer 0. Layer 0 не вызывает ничего выше себя.
- Layer 1 НЕ ДОЛЖЕН импортировать Layer 2. Layer 0 НЕ ДОЛЖЕН импортировать Layer 1 или Layer 2.
- Layer 2 НЕ ДОЛЖЕН напрямую вызывать LLM. Доступ к LLM ограничен агентами Layer 1 через `get_model()`.
- **Модератор** детерминирован и находится в Layer 1 (`orchestrator/`). Ни один LLM не участвует в управлении потоком или проверке безопасности.

## Вспомогательные услуги

Вспомогательные сервисы находятся вне цепочки слоёв. Они могут обращаться к слою 1, но НЕ должны напрямую обращаться к слою 2 или слою 0.

| Сервис | Роль | Поверхность вызова |
|---------|------|--------------|
| Документатор | Аудит документации и делегированные записи | Вызывается точкой входа оператора уровня 2; записи с поддержкой LLM используют порт исполнения уровня 1 |
| Сохранение JSON | Хранилище состояния сессии (`sessions/<id>/`) | Используется `persistence/` уровня 1; только локально, не фиксируется |

## Режимы работы

**Режим резервного копирования** — это режим работы, который заменяет основанный на коде **Модератор** до его внедрения (см. `fallback/index.md`). Он функционирует через именованные субагенты, запускаемые через данный каркас агентов. Сессии резервного режима исключены из требований `SessionManifest` (см. `execution-runtime/index.md` §Правило пространства имен) и разделяют только формат **артефакта** с канонической спецификацией. Основанный на коде **Модератор**, после внедрения, заменит резервный режим как режим по умолчанию для разработки.

## Путь миграции

Если оркестрация выходит за пределы Layer 1, извлеките ядро оркестрации за публичным интерфейсом Layer 1. Границы слоев и правило Layer 0 остаются неизменными.

## Улучшения

Все шесть функциональных улучшений из Архитектуры B интегрированы; ни одно из них не требует изменений в границах слоёв. Отложенные элементы — каталог ScenarioLoader, цепочка миграции схемы, классификатор быстрого обзора, Typer CLI, контрольные точки/возобновление, распределённая блокировка — перечислены в **Документе консенсуса**, который стал основой для данной редакции, и будут отслеживаться в спецификациях сервиса.

См.: `layer-0.md`, `layer-1.md`, `layer-2.md`, `decisions/index.md`.
