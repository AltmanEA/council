## Назначение

Детерминированное выполнение всех правил протокола. Отсутствие зависимостей от сторонних фреймворков. Чистые функции на Python. Возможность тестирования путем прямого импорта.

## Контракт интерфейса

```python
def evaluate_consensus(role_statuses: list[dict]) -> ConsensusVerdict
def validate_subject_references(subjects: list[dict], text: str) -> list[ValidationResult]
def extract_role_status(review_text: str) -> RoleStatus | InvalidFormat
def check_justification_format(finding: dict) -> FormatValid | FormatInvalid
```

### extract_role_status() — Подпись и тип возвращаемого замечания

```python
def extract_role_status(review_text: str) -> RoleStatus | InvalidFormat
```

Возвращает `RoleStatus` с `extraction = parsed` в случае успеха или артефакт `InvalidFormat` при ошибке парсинга. Потребители НЕ ДОЛЖНЫ использовать статус по умолчанию из ответа с некорректным форматом; см. §Политика InvalidFormat для обработки сессии. Слой 1 передает этот тип возврата непосредственно в конвейер вычисления консенсуса.

### InvalidFormat

Создано Layer 0 `extract_role_status()`, когда текст обзора не может быть разобран (перечисление статуса не распознано, отсутствуют обязательные поля). Потребители НЕ ДОЛЖНЫ выводить статус по умолчанию; сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`.

| Поле | Тип | Обязательно | Правило |
|-------|------|----------|------|
| `error_code` | string | да | Всегда `invalid-format` |
| `raw_text_hash` | string | да | `sha256` исходного текста отзыва, отправленного ролью |
| `parse_attempted` | boolean | да | `true` — указывает, что была предпринята попытка, но она не удалась |
| `role_id` | string \| null | нет | Если известно из контекста конверта; отсутствует, если сам отзыв некорректен |
| `session_id` | string \| null | нет | Если известно из контекста конверта; отсутствует, если сам отзыв некорректен |

## Правила границ

- Вызывается только Layer 1 (выполнение роли). Никогда не доступен напрямую для Layer 2 (инструменты точки входа). Если Layer 2 нуждается в поведении протокола, он вызывает через Layer 1.
- На этом слое запрещены импорты фреймворков. Никаких LangChain, LangGraph, FastAPI, зависимостей от SQLite.

## Инварианты (ADR-001: Структурные утверждения + тесты, основанные на свойствах)

Всё это обеспечивается с помощью явных утверждений `assert` и тестов свойств Hypothesis. Ни одна LLM не участвует в проверке безопасности.

| Инвариант | Описание |
|-----------|-------------|
| Наличие основной роли | Все роли основного уровня активны по умолчанию; исключение требует наличия `locked_roles` + `operator_approval: true` в SessionManifest (service-contract §SessionManifest). Отсутствие роли основного уровня без одобрения является блокирующей ошибкой (PROT.001). |
| Целостность эскалации | Пути эскалации не могут быть удалены или ослаблены любым параметром |
| Неизменность консенсуса | Логика вычисления консенсуса не может быть переопределена конфигурацией сценария |
| Обязательность обоснования | Проверка обоснования критического вывода всегда выполняется независимо от сложности задачи |
| Правило блокировки по уровню серьёзности | Вносить вклад в блокировку задачи могут только уровни серьёзности «средний» и выше |
| Структурная проверка позиции | Обнаружение расхождений использует машиночитаемые поля позиции, а не текстовую интерпретацию |

## Постоянство

**Фаза** состояния сериализуется в отдельные JSON-файлы в `sessions/<id>/`. Между сессиями нет общего состояния. Только кратковременные задачи — ACID не требуется. SQLite не используется. Чекпоинты не сериализуются через pickle. Обычный JSON с отсортированными ключами при записи.
