## Назначение

Все внешние интерфейсы взаимодействия между операторами-людьми и внутренними слоями. Слой 2 преобразует внешние запросы в вызовы слоя 1; он не содержит логики протоколов и не выполняет вызовы LLM. В версии MVP поставляется один транспорт — MCP stdio. CLI и REST остаются отложенными адаптерами поверх тех же библиотечных функций.

## Транспорт (MVP: MCP stdio)

Поверхность оператора предоставляет небольшой набор инструментов MCP: отправка задачи, проверка статуса сессии, разрешение эскалации, получение артефактов и вызов Документатора (`audit`, `delegate`). Каждый инструмент проверяет свои входные данные, аутентифицирует вызывающего и обращается к слою 1. Ни один инструмент не обращается к слою 0 напрямую.

## Структурированная проверка ввода

Модели Pydantic на шлюзе входа проверяются до того, как какие-либо данные достигнут уровня 0. Являются дополнением, а не заменой проверок уровня 0.

### Версионирование схемы (ADR-005)

ВНЕШНИЙ МАППЕР — ЗАРЕЗЕРВИРОВАНО ДЛЯ БУДУЩЕГО ИСПОЛЬЗОВАНИЯ. Файл внешнего маппера `schema_versions.json` и цепочка его миграций НЕ будут включены в MVP. Этот раздел существует исключительно для документирования принятого решения: на этапе MVP функционал миграции отсутствует; поле `schema_version` в схемах Service Contract предусмотрено только для будущих расширений. Когда функционал миграции будет реализован, он будет поддерживать только одноуровневые шаги преобразования (от старой версии к следующей), при этом любые изменения потребуют одобрения через PR.

Применяются правила валидации:

- `ConfigDict(extra="forbid")` — неизвестные поля отклоняются, а не поглощаются молча
- Защита от глубокой вложенности (максимум ~32 уровня) для предотвращения сбоев из-за некорректного ввода
- Плавная деградация — любая ошибка валидации формирует структурированный ответ, удобный для оператора, без утечки трассировки стека

## Локализация ошибок (ADR-003)

Детерминированная таблица поиска, сопоставляющая коды ошибок с локализованными сообщениями. Без генерации с помощью LLM. Двойной вывод записей об ошибках: технический (сырой контекст отладки) + локализованный (для операторов).

### Таксономия кодов ошибок

| Префикс | Домен | Примеры |
|--------|--------|----------|
| ВАЛ. | Ошибки валидации | несоответствие схемы, отсутствие обязательного поля |
| ПРОТ. | Нарушения протокола | ошибка вычисления консенсуса, ошибка перехода фазы |
| МОДЕЛЬ. | Проблемы с провайдером LLM | превышение лимита, ошибка аутентификации, таймаут |
| ВВОД/ВЫВОД. | Файловая система/сохранение | ошибка записи, повреждение чтения |
| КОНФИГ. | Ошибки конфигурации | отсутствие ключа API, недопустимый сценарий |
| АВТ. | Ошибки аутентификации/авторизации | истекшие учетные данные, недопустимая подпись, неизвестный вызывающий, отозванные учетные данные |

Уровень детализации, настраиваемый оператором: минимальный (высокоуровневое обобщение), сбалансированный (по умолчанию), полный (включены технические детали, позволяющие принимать решения).

Кодифицированное соблюдение правил: каждый новый код ошибки требует pull request, который одновременно добавляет запись кода и запись локализации. Проверка CI завершается ошибкой, если новый код существует без соответствующей локализации.

## Поверхность оператора

Поверхность оператора — это адаптер, а не оркестратор. Она аутентифицирует вызывающего, проверяет запрос и обращается к слою 1. Глаголы оператора, классы идентичности, доставка эскалации и шлюз `pre_check` указаны в спецификации «Поверхность оператора и эскалация». Эскалация работает по принципу «стоп-и-возобновление»: сессия является долговечной, и оператор разрешает её в более позднем вызове.

## Typer CLI (отложено до Фазы 2)

Локально-ориентированный скриптуемый интерфейс. Один из нескольких адаптеров транспорта, использующих те же базовые функции библиотеки, что и инструменты MCP.

- Автодополнение по Tab, автоматически генерируемая справка
- Флаг `--no-color` (также реагирует на переменную окружения NO_COLOR)
- Режим `--output json/yaml` для программной обработки
- Разделение stdout/stderr: структурированный результат выводится в stdout, прогресс/предупреждения/ошибки — в stderr
- Передача аргументов через этап санитизации после валидации Pydantic

## Перемещено в слой 1

Ниже приведены замечания, относящиеся к плоскости управления и принадлежащие слою 1, а не слою 2:

- Сопоставление и загрузка **Сценарий** (`ScenarioLoader`).
- Быстрая проверка классификации SIMPLE/COMPLEX (отложено; хук обновления зарезервирован в **Фаза** конечного автомата состояния).
- Контрольная точка/возобновление и сохранение **Сессия**.

## Вспомогательные услуги

Документатор не является компонентом второго уровня. Это Вспомогательный сервис, вызываемый через операторскую поверхность данного уровня; записи, поддерживаемые LLM, используют Порт исполнения первого уровня. Второй уровень никогда не вызывает LLM от имени Документатора. Полная спецификация: `../documenter-service/index.md`; размещение: `../index.md`.
