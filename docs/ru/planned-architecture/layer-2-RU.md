## Назначение

Все внешние интерфейсы взаимодействия между операторами-людьми и внутренними слоями. Слой 2 преобразует внешние запросы в вызовы слоя 1; он не содержит логики протоколов и не вызывает LLM. В версии MVP поставляется один транспорт — MCP stdio. CLI и REST остаются отложенными адаптерами поверх одних и тех же библиотечных функций.

## Транспорт (MVP: MCP stdio)

Точка входа оператора (ранее Поверхность оператора) предоставляет небольшой набор инструментов MCP: отправить задачу, проверить статус сессии, разрешить эскалацию, получить артефакты и вызвать Документатор (`audit`, `delegate`). Каждый инструмент проверяет свои входные данные, аутентифицирует вызывающего и обращается к слою 1. Ни один инструмент не обращается к слою 0 напрямую.

## Структурированная проверка ввода

Модели Pydantic на шлюзе входа проверяются до того, как какие-либо данные достигнут уровня 0. Являются дополнением, а не заменой проверок уровня 0.

### Версионирование схемы (ADR-005)

ВНЕШНИЙ МАППЕР — ЗАРЕЗЕРВИРОВАНО ДЛЯ БУДУЩЕГО ИСПОЛЬЗОВАНИЯ. Файл внешнего маппера `schema_versions.json` и его цепочка миграций НЕ будут включены в состав MVP. Данный раздел существует исключительно для фиксации принятого решения: на этапе MVP функционал миграции отсутствует; поле `schema_version` в схемах Service Contract предусмотрено только для будущих расширений. Когда функционал миграции будет реализован, он будет поддерживать только одноуровневые шаги преобразования (от старой версии к следующей), при этом любые изменения потребуют одобрения через PR.

Применены правила валидации:

- `ConfigDict(extra="forbid")` — неизвестные поля отклоняются, а не поглощаются молча
- Защита от глубокой вложенности (максимум ~32 уровня) для предотвращения сбоев из-за патологических входных данных
- Плавная деградация — любая ошибка валидации формирует структурированный ответ, удобный для оператора, без утечки трассировки стека

## Локализация ошибок (ADR-003)

Детерминированная таблица поиска, сопоставляющая коды ошибок локализованным сообщениям. Без генерации с помощью LLM. Двойной вывод записей об ошибках: технический (сырой контекст отладки) + локализованный (для операторов).

### Таксономия кодов ошибок

| Префикс | Домен | Примеры |
|--------|--------|----------|
| VAL. | Ошибки валидации | несоответствие схемы, отсутствие обязательного поля |
| PROT. | Нарушения протокола | ошибка вычисления консенсуса, ошибка перехода фазы |
| MODEL. | Проблемы с провайдером LLM | лимит запросов, ошибка аутентификации, таймаут |
| IO. | Файловая система/хранилище | ошибка записи, повреждение чтения |
| CONFIG. | Ошибки конфигурации | отсутствие ключа API, недопустимый сценарий |
| AUTH. | Ошибки аутентификации/авторизации | истек учетные данные, недопустимая подпись, неизвестный вызывающий, отозванные учетные данные |

Уровень детализации, настраиваемый оператором: минимальный (высокоуровневое обобщение), сбалансированный (по умолчанию), полный (включены технические детали, позволяющие принимать решения).

Кодифицированное соблюдение правил для новых кодов ошибок: каждый новый код ошибки требует pull request (PR), который одновременно добавляет запись кода и запись локализации. Проверка CI завершается ошибкой, если новый код существует без соответствующей записи локализации.

## Точка входа оператора

Точка входа оператора — это адаптер, а не оркестратор. Она аутентифицирует вызывающую сторону, проверяет запрос и обращается к слою 1. Глаголы оператора, классы идентичности, доставка эскалации и шлюз `pre_check` указаны в спецификации Точка входа оператора и Эскалация. Эскалация работает по принципу «стоп-и-возобновление»: сессия является долговременной, и оператор разрешает её при последующем вызове.

## Typer CLI (отложено до Фазы 2)

Локально-ориентированный скриптуемый интерфейс. Один из нескольких адаптеров транспорта, использующих те же базовые функции библиотеки, что и инструменты MCP.

- Автодополнение по Tab, автоматически генерируемая справка
- Флаг `--no-color` (также реагирует на переменную окружения NO_COLOR)
- Режим `--output json/yaml` для программной обработки
- Разделение stdout/stderr: структурированный результат выводится в stdout, прогресс/предупреждения/ошибки — в stderr
- Передача аргументов через санитизацию после валидации Pydantic

## Перемещено в слой 1

Следующие замечания относятся к плоскости управления и принадлежат уровню 1, а не уровню 2:

- Сопоставление и загрузка Сценария (`ScenarioLoader`).
- Быстрая проверка классификации SIMPLE/COMPLEX (отложено; хук обновления зарезервирован в конечном автомате состояния Фазы).
- Контрольная точка/возобновление и сохранение Сессии.

## Вспомогательные услуги

Документатор не является компонентом уровня 2. Это Вспомогательный сервис, вызываемый через Точку входа оператора данного уровня; записи, поддерживаемые LLM, используют Порт исполнения уровня 1. Уровень 2 никогда не вызывает LLM от имени Документатора. Полная спецификация: `../documenter-service/index.md`; размещение: `../index.md`. См.: `operator-ingress/index.md`.
