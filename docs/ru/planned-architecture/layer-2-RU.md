## Назначение

Все внешние интерфейсы между операторами-людьми и внутренними слоями. Слой 2 переводит внешние запросы в вызовы Слой 1; он не содержит логики протокола и не выполняет вызовов LLM. MVP выпускает один транспорт — MCP stdio. CLI и REST остаются отложенными адаптерами над теми же функциями библиотеки.

## Транспорт (MVP: MCP stdio)

Поверхность оператора expose небольшой набор MCP инструментов: отправить задачу, проверить статус сессии, разрешить эскалацию, получить артефакты и вызвать Документер (`audit`, `delegate`). Каждый инструмент валидирует входные данные, аутентифицирует вызывающего и обращается к Слой 1. Ни один инструмент не вызывает Слой 0 напрямую.

## Структурированная валидация входа

Pydantic модели на входе, валидирующие перед тем, как любые данные достигнут Слой 0. Дополняющие, а не заменяющие проверки Слой 0.

### Версионирование схемы (ADR-005)

EXTERNAL MAPPER — ЗАДЕЛЕНО ДЛЯ БУДУЩЕГО ИСПОЛЬЗОВАНИЯ. Файл внешних мапперов `schema_versions.json` и цепочка миграций НЕ БУДУТ выпущены в MVP. Этот раздел существует исключительно для документирования принятого решения: отсутствие возможности миграции в MVP; поле `schema_version` в схемах Service Contract существует только для будущих дополнений. Когда миграция будет реализована позднее, она будет поддерживать только одноуровневые шаги преобразования (old→next), требуя одобрения PR для любых изменений.

Правила валидации, которые применяются:

- `ConfigDict(extra="forbid")` — неизвестные поля отклоняются, не поглощаются молча
- Защита от глубокого вложения (~32 уровня макс.), чтобы предотвратить крахи от патологических входных данных
- Graceful degradation — любая ошибка валидации порождает структурированный ответ, дружественный оператору, никогда не протекает stack trace

## Локализация ошибок (ADR-003)

Детерминированная таблица lookup, отображающая коды ошибок на локализованные сообщения. Никакой генерации LLM. Двойной вывод записей ошибок: технический (сырой контекст отладки) + локализованный (для оператора).

### Таксономия кодов ошибок

| Префикс | Домен | Примеры |
|--------|--------|----------|
| VAL. | Ошибки валидации | несовпадение схемы, отсутствие обязательного поля |
| PROT. | Нарушения протокола | ошибка вычисления консенсуса, ошибка перехода фазы |
| MODEL. | Проблемы провайдера LLM | rate limit, ошибка auth, timeout |
| IO. | Файловая система / сохранение | ошибка записи, corruption чтения |
| CONFIG. | Ошибки конфигурации | отсутствующий API key, невалидный сценарий |
| AUTH. | Ошибки аутентификации / авторизации | истёкшее учётное удостоверение, невалидная подпись, неузнанный вызывающий, отозванное учётное удостоверение |

Уровень подробности, настраиваемый оператором: минимальный (сильно суммированный), сбалансированный (по умолчанию), полный (включены технические детали, позволяющие действовать).

Кодифицированное принудительное применение: каждый новый код ошибки требует PR, добавляющий одновременно entry кода и entry локализации. CI проверка не проходит, если существует новый код без соответствующей локализации.

## Поверхность оператора

Поверхность оператора — это адаптер, а не оркестратор. Она аутентифицирует вызывающего, валидирует запрос и обращается к Слой 1. Глаголы оператора, классы идентичности, доставка эскалации и gate `pre_check` специфицированы в спецификации «Поверхность оператора и эскалация». Эскалация — stop-and-resume: сессия долговечна, и оператор разрешает её при следующем вызове.

## Typer CLI (отложено до Фаза 2)

Local-first скриптуемый интерфейс. Один из множества адаптеров транспорта, разделяющих те же базовые функции библиотеки, что и MCP инструменты.

- Tab-completion, автоматически сгенерированная помощь
- Флаг `--no-color` (также реагирует на переменную окружения NO_COLOR)
- Режим `--output json/yaml` для машинного потребления
- Разделение stdout/stderr: структурированный результат на stdout, прогресс/предупреждения/ошибки на stderr
- Проход санитизации аргументов после валидации Pydantic

## Перемещено в Слой 1

Следующие являются concerns управляющей плоскости и принадлежат Слой 1, а не Слой 2:

- Matching и загрузка сценария (`ScenarioLoader`).
- Быстрый анализ SIMPLE/COMPLEX классификации (отложено; хук апгрейда зарезервирован в фазной машине состояний).
- Checkpoint/resume и сохранение сессии.

## Вспомогательные сервисы

Documenter не является компонентом Слой 2. Это вспомогательный сервис, вызываемый через поверхность оператора этого слоя; записи с LLM используют порт выполнения Слой 1. Слой 2 никогда не вызывает LLM от имени Documenter. Полная спецификация: `../documenter-service/index.md`; размещение: `../index.md`.
