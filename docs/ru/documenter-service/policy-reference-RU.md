## Назначение

Авторитетная схема файла политик Документатора: определения полей, правила валидации при загрузке, параметры операционной настройки и пошаговый рабочий процесс авторизации ступеней. Семантика протокола, которую настраивают эти поля (ступени доверия, протокол безопасности, контракты интерфейсов), определена в `documenter-service/index.md`; структуры данных рантайма (хранилище хешей, журнал намерения, схема событий) определены в `documenter-service/configuration-guide.md`. Этот документ не определяет собственного поведения — он является конфигурационной поверхностью для поведения, определённого в других местах.

## Файл политики

YAML-конфигурация, определяющая, какие операции разрешены на каждой ступени, и режимы соответствия. Пишется и поддерживается оператором. Автопродолжение по времени не является частью модели: одобрение — всегда явное действие оператора внутри вызова `delegate()`, а единственный путь автовыполнения — автоприменение по паттерну на Ступени 3 (см. §Trust Tiers и §Approval semantics в основной спецификации, `documenter-service/index.md`).

**Правило валидатора:** Документатор ДОЛЖЕН отклонять загрузку любого файла политик, где `allowed_operations` непусто, а `active_tier < 2`. Это предотвращает мисконфигурацию при развёртывании. **Правило полномочий:** Записи политик могут только ужесточать встроенный базовый уровень классификации доверия из основной спецификации (§Trust Classification): запись `allowed_operations` может требовать `review` там, где таблица допускает `safe`, но комбинация политики, авторизующая `trust_level` ниже *статического базового уровня* для её `change_type`, недействительна и ДОЛЖНА быть отклонена при загрузке — Документатор трактует её как ошибку мисконфигурации, согласно правилу валидатора выше.

**Правило совместимости:** Каждое поле в §Справочник полей необязательно, кроме `version`, `active_tier` и `allowed_operations`. Файл политик, написанный под более раннюю версию схемы, загружается успешно: отсутствующие поля разрешаются в значения по умолчанию, перечисленные ниже, а повышение версии схемы не подразумевает удаления или переименования какого-либо поля.

```yaml
documenter_policy:
  version: "0.2.0"
  active_tier: 0                  # 0 = audit-only (MVP default)
  allowed_operations: []          # inert at active_tier < 2; populate when advancing
  glossary_enforcement: draft     # draft | active — controls noise reduction
  audit_freshness: 30             # minutes; max age of audit_id accepted by delegate() pre-audit gate
  lock_wait_timeout: 30           # seconds; advisory lock acquisition wait before abort
  retry_backoff_base: 1           # seconds; exponential backoff base on hash_mismatch retry
  retry_max_attempts: 3           # count; retry attempts before escalation to operator
  operator_approval_timeout: 300  # seconds; synchronous wait for approve/reject inside delegate()
  notification_mode: inline       # inline only — no asynchronous notification channel exists
  approval_expiry_window: 30            # minutes; maximum time between Tier 2+ authorization and the first delegate() invocation under that approval
  rescan_batch_ceiling: 50        # documents per full-rescan invocation before partial-report return
  glossary_staleness_days: 30     # days since last glossary modification; terms appearing ≥3 times within this window are flagged as missing
  briefing_ref: null              # path to operator briefing artifact; required when active_tier >= 2
```

На Ступенях 0–1 `allowed_operations` должно оставаться пустым независимо от содержимого. Оператор обновляет этот файл явно при продвижении ступеней. Документатор отказывается выполнять любую операцию, не перечисленную в нём.

**Исключение для предварительного просмотра:** Вызовы `delegate()` без намерения записи (режим preview, возвращающий diff без применения изменений) не подлежат проверке `allowed_operations` ни на одной ступени. Именно на это исключение опирается Ступень 1 для формирования diff. Такие вызовы всегда возвращают вычисленный diff, но никогда не изменяют файлы. Предварительный просмотр управляется булевым параметром `preview` (§Interfaces, delegate()) — когда он установлен в `true`, проверки ступени и вентиля не применяются; проверяется лишь схемная корректность обязательных полей (`target_id`, `change_type`, `diff`).

### Справочник полей

| Поле | Тип | Обязательно | По умолчанию | Описание |
|-------|------|----------|---------|-------------|
| `version` | string | Да | `"0.2.0"` | Версия схемы политик для обнаружения совместимости |
| `active_tier` | int | Да | `0` | Текущая ступень доверия (0–3). Должен соответствовать таблице ступеней (§Trust Tiers, основная спецификация). |
| `allowed_operations` | array | Да | `[]` | Операции, авторизованные на текущей ступени. Пусто ниже Ступени 2. Может только ужесточать базовый уровень доверия (§Правило полномочий выше). |
| `approval_expiry_window` | int | Нет | `30` | Максимальное время (минуты), по истечении которого не одобренный `approval_id` истекает. Диапазон: 5–1440 (от 5 минут до 24 часов). Используется вместе с внеполосным вызовом `documenter.approve(approval_id, operator_id)`, описанным в operator-surface §Documenter Integration. |
| `audit_freshness` | int | Нет | `30` | Максимальный возраст (минуты) `audit_id`, принимаемого вентилем предварительного аудита `delegate()`. Вентиль дополнительно валидирует покрытие области (точное совпадение или `*`), блокирующие выводы и завершённость сканирования (`has_remaining` не должно быть `true`) по реестру аудита (`documenter-service/configuration-guide.md`, §Audit Registry). Установите `0`, чтобы полностью отключить вентиль (аудит не требуется; `audit_id` игнорируется, если предоставлен). Любое иное значение обеспечивает окно свежести. |
| `briefing_ref` | string | Нет | `null` | Путь к заархивированному артефакту брифинга оператора, документирующему объём делегированных полномочий. ДОЛЖЕН быть не-null при `active_tier >= 2` (§Рабочий процесс авторизации, шаг 4). |
| `glossary_enforcement` | enum | Нет | `draft` | Управляет снижением шума соответствия глоссарию (§Glossary Compliance, руководство по конфигурации). |
| `glossary_staleness_days` | int | Нет | `30` | Дни с момента последнего изменения глоссария; термины, встречающиеся ≥3 раз в этом окне, помечаются как отсутствующие (§Glossary Compliance, руководство по конфигурации). |
| `lock_wait_timeout` | int | Нет | `30` | Секунды ожидания блокировки уровня операции перед прерыванием с ошибкой о владельце блокировки, описанной в §Safety Protocol #2 (основная спецификация). |
| `notification_mode` | enum | Нет | `inline` | Режим доставки сигналов, видимых оператору. `inline` — единственное принимаемое значение в MVP: сигналы, diff и вердикты возвращаются внутри ответа на вызов. Нераспознанные значения отклоняются при загрузке. |
| `operator_approval_timeout` | int | Нет | `300` | Секунды, которые активный вызов `delegate()` ожидает явного approve/reject перед излучением `error_category: operator_timeout`. Не окно автоодобрения (§Approval semantics, основная спецификация). |
| `rescan_batch_ceiling` | int | Нет | `50` | Документов, обрабатываемых за вызов полного пересканирования. При достижении ответ включает `has_remaining: true` и токен продолжения `scan_cursor`; его обратная передача возобновляет сканирование с точки остановки предыдущего вызова. Частичные сканирования никогда не авторизуют делегаты для непросканированных документов — оператор должен завершить все пакеты до разрешения делегирования. Фоновое выполнение отсутствует. |
| `retry_backoff_base` | int | Нет | `1` | Базовая задержка (секунды) экспоненциальной задержки с джиттером, используемой повторными вызовами (§Conflict Resolution, руководство по конфигурации). |
| `retry_max_attempts` | int | Нет | `3` | Максимальное число повторных вызовов после `hash_mismatch`, прежде чем Документатор эскалирует оператору вместо повторной попытки. |
| `temperature` | float | Нет | `0.1` | Случайность генерации LLM; бо́льшие значения увеличивают разнообразие (диапазон: 0.0–2.0). Применяется на уровне вывода ролевого агента (§Zero silent defaults, layer-1.md). |
| `top_p` | float | Нет | `0.9` | Параметр сэмплирования по ядру (nucleus sampling); токены с кумулятивной вероятностью ниже этого порога исключаются (диапазон: 0.0–1.0). Применяется на уровне вывода ролевого агента (§Zero silent defaults, layer-1.md). |
| `frequency_penalty` | float | Нет | `0.0` | Снижает повторение токенов; положительные значения штрафуют повторяющиеся токены (диапазон: -2.0–2.0). Нейтральное значение по умолчанию, задаётся явно, а не выводится (§Zero silent defaults, layer-1.md). |

### Записи по операциям

Записи по операциям в `allowed_operations` следуют этой структуре:

```yaml
# Tier 2+ operation entry (default type — no explicit type field needed):
allowed_operations:
  - type: operation          # operation | pattern — omitted defaults to "operation"
    change_type: update      # update | split | create_ru | custom
    trust_level: safe        # safe | review — must not fall below the static floor (§Trust Classification, main spec)
    targets: []              # empty = all docs; list = specific manifest IDs
    requires_diff_preview: true  # always enforced at Tier 2+

# Tier 3 pattern entry (enables auto-apply for matching changes):
  - type: pattern
    pattern_id: "auto-bump-patch"   # unique identifier for this pattern
    pattern_description: "Deterministic patch-level version bumps in CHANGELOGS/*.changes.md and index.md metadata"
    match_criteria:
      change_type: update
      file_pattern: "CHANGELOGS/*.changes.md"  # glob-style path pattern; empty = match any file
    trust_level: safe
    requires_diff_preview: true
```

Поля записи паттерна:

| Поле | Тип | Описание |
|-------|------|-------------|
| `type` | `operation` \| `pattern` | Дискриминатор. При отсутствии по умолчанию `operation` (обратно совместимо). |
| `pattern_id` | string | Уникальный идентификатор этого паттерна (kebab-case). |
| `pattern_description` | string | Человекочитаемое описание того, что сопоставляет паттерн. |
| `match_criteria.change_type` | enum | Ограничивает сопоставление конкретным `change_type`. |
| `match_criteria.file_pattern` | string | Glob-подобный шаблон пути относительно корня рабочего пространства. `*` = любые символы кроме `/`, `**` = любые символы включая `/`, `?` = один символ кроме `/`. Недействительные шаблоны отклоняются при загрузке политики. |

## Операционная настройка

Какая рукоятка управляет каким путём отказа. Все значения — поля политики из §Справочник полей; ни одно не требует изменения кода или перезапуска сверх перезагрузки политики.

| Отказ или давление | Поле | При исчерпании |
|---------------------|-------|---------------|
| Одновременный `delegate()` от другого агента | `lock_wait_timeout` | Прервать до любой записи; в ошибке указаны PID/IP владельца блокировки и метка времени захвата (§Safety Protocol #2) |
| Файл изменился между сканированием и записью | `retry_backoff_base` + `retry_max_attempts` | Эскалировать оператору; заново запустить `audit()` для свежего `audit_id` |
| Оператор отсутствует при представленном diff | `operator_approval_timeout` | Излучить `error_category: operator_timeout`; ничего не записывается, подготовленные файлы `.tmp` отбрасываются |
| Ожидание внеполосных оповещений | `notification_mode` | Неприменимо — асинхронного канала не существует; см. §Семантика оповещений |
| Полное пересканирование превышает число документов | `rescan_batch_ceiling` | Ответ включает `has_remaining: true` и `scan_cursor`; оператор повторно вызывает `audit(scan_cursor=<value>)`, чтобы возобновить с точки остановки предыдущего вызова |
| Устаревший, недействительный или неполный `audit_id`, представленный в `delegate()` | `audit_freshness` | Отклонить с `error_category: audit_mismatch` (реестр отсутствует/истёк/несоответствие области) или `error_category: blocking_finding` (присутствуют выводы high/critical либо сканирование незавершено, `has_remaining: true`) с действием повторного запуска `audit()`. Если реестр отсутствует/нечитаем, вентиль ЗАКРЫВАЕТСЯ ОТКАЗОМ — все записи запрещены до аутентифицированного переопределения через `documenter.override_gate(reason, operator_id)` |

### Семантика оповещений

У Документатора нет подсистемы оповещений: нет таймера, демона, канала push, фонового опроса (см. §Purpose и §Approval semantics, основная спецификация). Каждый видимый оператору сигнал — отчёт аудита, предварительный просмотр diff, запрос о конфликте блокировок, запрос одобрения — формируется внутри синхронного ответа на вызов, который его породил, и дополнительно сохраняется в журнале событий только для добавления (§Event Schema, руководство по конфигурации) для последующего воспроизведения. `notification_mode` существует, чтобы сделать это явным и зарезервировать пространство имён поля: введение асинхронного канала было бы изменением модели основной спецификации, а не правкой политики, и требует нового значения `notification_mode` плюс определённого контракта доставки.

## Рабочий процесс авторизации

Процедура продвижения возможности записи. Каждый шаг — дискретное действие оператора; Документатор никогда не выполняет шаг самостоятельно. Шаги 1–3 предшествуют первому вызову Ступени 2+; основная спецификация §Trust Tiers указывает и файл политики, и брифинг как обязательные предпосылки.

1. **Аудит на текущей ступени.** Запустите `audit("*")` и устраните выводы `high` и `critical`. Ступень 2+ над некомплаентным корпусом автоматизирует дрейф, а не уборку.
2. **Составьте файл политики.** Напишите `documenter_policy.yml` согласно §Файл политики: задайте предполагаемые сочетания `change_type` + `trust_level` + `targets` в `allowed_operations` и настройте операционные рукоятки согласно §Операционная настройка.
3. **Валидируйте автономно.** Загрузите файл-кандидат в режиме только проверки. Загрузка падает на: непустом `allowed_operations` ниже Ступени 2 (правило валидатора), `trust_level` ниже выводимого базового уровня для его `change_type` (правило полномочий) либо на нераспознанном значении `notification_mode`.
4. **Зафиксируйте брифинг.** Напишите и заархивируйте брифинг оператора — какие документы и значения `change_type` делегируются, максимальное число документов, которые может затронуть один вызов, и процедура отката — затем установите `briefing_ref` на его путь. Этот артефакт — человекочитаемый аналог `allowed_operations`.
5. **Продвиньте ступень.** Установите `active_tier` в той же правке, что и `briefing_ref`, чтобы частичная правка не оставила Ступень 2+ без ссылки на брифинг.
6. **Первая запись на новой ступени.** Вызовите `delegate()` на единственной цели с низким риском и со свежим `audit_id`. Просмотрите diff поэлементно независимо от ступени; Ступень 2 даёт возможность, а не ослабление контроля.
7. **Оцените для Ступени 3.** Продвигайтесь только по задокументированным свидетельствам: доля одобрения ≥90% на Ступени 2 за предшествующие две недели журнала событий (§Tier Selection Guidance, основная спецификация), вычислимая из полей `decision` в журнале событий (§Event Schema, руководство по конфигурации). Авторизованные паттерны затем явно перечисляются в `allowed_operations` как записи `type: pattern` с `pattern_id`, `pattern_description` и `match_criteria` (§Записи по операциям); Ступень 3 никогда не выводит паттерн, который не авторизовал оператор.

**Откат:** установите `active_tier` на меньшее значение. Изменение вступает в силу при следующем вызове; выполняющийся `delegate()` завершается на той ступени, на которой был принят, удерживая блокировку уровня операции согласно §Safety Protocol #2.
