## Назначение

Авторитетная схема для файла политики Документатора: определения полей, правила проверки во время загрузки, параметры операционный настройки и пошаговый рабочий процесс авторизации по уровням. Семантика протокола, которую настраивают эти поля (уровни доверия, протокол безопасности, контракты интерфейсов), определена в `documenter-service/index.md`; структуры данных во время выполнения (хранилище хэшей, журнал намерения, схема событий) определены в `documenter-service/configuration-guide.md`. Этот документ не определяет собственного поведения — это поверхность конфигурации для поведения, определённого в других местах.

## Файл политики

YAML-конфигурация, определяющая, какие операции разрешены на каждом уровне и в каких режимах соответствия. Создаётся и поддерживается оператором. Автоматическое продолжение на основе времени не является частью модели: одобрение всегда является явным действием оператора в рамках вызова `delegate()`, а единственным путём автоматического выполнения является автоматическое применение на основе шаблонов уровня 3 (см. §Уровни доверия и §Семантика одобрения в основной спецификации, `documenter-service/index.md`).

**Правило валидатора:** Документатор обязан отклонять загрузку любого файла политики, в котором `allowed_operations` не пуст, а `active_tier < 2`. Это предотвращает ошибки конфигурации при развертывании. **Правило авторизации:** Записи политики могут лишь повышать базовый уровень доверия, установленный встроенной классификацией в основной спецификации (§Trust Classification): запись в `allowed_operations` может требовать `review` там, где таблица допускает `safe`, однако комбинация политик, разрешающая `trust_level` ниже *статического порога* для соответствующего `change_type`, является недействительной и должна быть отклонена на этапе загрузки — Документатор рассматривает это как ошибку конфигурации, что согласуется с приведенным выше правилом валидатора.

**Правило совместимости:** Все поля в §Field Reference являются необязательными, за исключением `version`, `active_tier` и `allowed_operations`. Файл политики, написанный для более ранней версии схемы, загружается успешно: отсутствующие поля принимают замечания по умолчанию, указанные ниже, а увеличение версии схемы не подразумевает удаление или переименование каких-либо полей.

```yaml
documenter_policy:
  version: "0.2.0"
  active_tier: 0                  # 0 = audit-only (MVP default)
  allowed_operations: []          # inert at active_tier < 2; populate when advancing
  glossary_enforcement: draft     # draft | active — controls noise reduction
  audit_freshness: 30             # minutes; max age of audit_id accepted by delegate() pre-audit gate
  lock_wait_timeout: 30           # seconds; advisory lock acquisition wait before abort
  retry_backoff_base: 1           # seconds; exponential backoff base on hash_mismatch retry
  retry_max_attempts: 3           # count; retry attempts before escalation to operator
  operator_approval_timeout: 300  # seconds; synchronous wait for approve/reject inside delegate()
  notification_mode: inline       # inline only — no asynchronous notification channel exists
  approval_expiry_window: 30            # minutes; maximum time between Tier 2+ authorization and the first delegate() invocation under that approval
  rescan_batch_ceiling: 50        # documents per full-rescan invocation before partial-report return
  max_diff_bytes: 524288          # bytes; maximum size of a decoded diff payload (default 512 KiB)
  sync_latency_budget_ms: 30000   # milliseconds; a synchronous call exceeding this budget returns a structured timeout error instead of blocking
  glossary_staleness_days: 30     # days since last glossary modification; terms appearing ≥3 times within this window are flagged as missing
  briefing_ref: null              # path to operator briefing artifact; required when active_tier >= 2
```

На уровнях 0–1 `allowed_operations` должен оставаться пустым независимо от содержимого. Оператор обновляет этот файл явно при переходе на новые уровни. Документатор отказывается выполнять любые операции, не указанные в списке.

**Исключение для предварительного просмотра:** Вызовы `delegate()`, не предполагающие запись (режим предварительного просмотра, возвращающий разницу без применения изменений), освобождаются от проверки `allowed_operations` на всех уровнях. Уровень 1 (Tier 1) специально опирается на это исключение для формирования разницы. Такие вызовы всегда возвращают вычисленную разницу, но никогда не изменяют файлы. Режим предварительного просмотра управляется с помощью булевого параметра `preview` (§Interfaces, delegate()) — при значении `true` не применяются ни валидация по уровням, ни принудительное выполнение ограничений; проверяется только корректность схемы обязательных полей (`target_id`, `change_type`, `diff`).

### Справочник по полям

| Поле | Тип | Обязательно | По умолчанию | Описание |
|-------|------|----------|---------|-------------|
| `version` | string | Да | `"0.2.0"` | Версия схемы политики для обнаружения совместимости |
| `active_tier` | int | Да | `0` | Текущая ступень доверия (0–3). Должна совпадать с таблицей ступеней доверия (§Ступени доверия, основной спецификации). |
| `allowed_operations` | array | Да | `[]` | Операции, разрешённые на текущей ступени. Пусто ниже 2-й ступени. Может только ужесточать базовый уровень доверия (§Правило авторитета выше). |
| `approval_expiry_window` | int | Нет | `30` | Максимальное время (в минутах) до истечения срока неутверждённого `approval_id`. Диапазон: 5–1440 (от 5 минут до 24 часов). Используется вместе с внеканальным вызовом `documenter.approve(approval_id, operator_id)`, указанным в `documenter-service/mvp-contract.md` §4 (канонический контракт утверждения). |
| `audit_freshness` | int | Нет | `30` | Максимальный возраст (в минутах) `audit_id`, принимаемого вратарём предварительного аудита `delegate()`. Вратарь дополнительно проверяет покрытие области (точное совпадение или `*`), заблокированные результаты и завершение сканирования (`has_remaining` не должно быть `true`) в реестре аудита (`documenter-service/configuration-guide.md`, §Реестр аудита). Установите `0`, чтобы полностью отключить вратарь (аудит не требуется; `audit_id` будет проигнорирован, если он предоставлен). Любое другое значение обеспечивает соблюдение окна свежести. |
| `briefing_ref` | string | Нет | `null` | Путь к архивированному артефакту брифинга оператора, документирующему область делегированных полномочий. ДОЛЖНО быть не равным null, когда `active_tier >= 2` (§Рабочий процесс авторизации, шаг 4). |
| `glossary_enforcement` | enum | Нет | `draft` | Управляет снижением шума соответствия глоссарию (§Соответствие глоссарию, руководство по конфигурации). |
| `glossary_staleness_days` | int | Нет | `30` | Дней с момента последней модификации глоссария; термины, появляющиеся ≥3 раза в течение этого окна, помечаются как отсутствующие (§Соответствие глоссарию, руководство по конфигурации). |
| `lock_wait_timeout` | int | Нет | `30` | Секунды ожидания блокировки на уровне операции перед прерыванием с ошибкой владельца блокировки, описанной в §Протокол безопасности #2 (основной спецификации). |
| `max_diff_bytes` | int | Нет | `524288` | Максимальный размер в байтах декодированного полезного груза `diff`/`diff_input` (по умолчанию 512 КиБ). Более крупный полезный груз отклоняется на входе со структурированной ошибкой до какой-либо обработки diff. |
| `notification_mode` | enum | Нет | `inline` | Режим доставки обращений к оператору. `inline` — единственное принимаемое значение в MVP: обращения, diff и вердикты возвращаются внутри ответа вызова. Неизвестные замечания отклоняются во время загрузки. |
| `operator_approval_timeout` | int | Нет | `300` | Секунды, которые активный вызов `delegate()` ожидает явного утверждения/отклонения перед выдачей `error_category: operator_timeout`. Не является окном автоутверждения (§Семантика утверждения, основной спецификации). |
| `rescan_batch_ceiling` | int | Нет | `50` | Документы, обрабатываемые за один вызов полного повторного сканирования. При достижении этого замечания ответ включает `has_remaining: true` и токен продолжения `scan_cursor`; передача его обратно возобновляет выполнение с того места, где остановился предыдущий вызов. Частичные сканирования никогда не авторизуют делегатов для несканированных документов — оператор должен завершить все пакеты, прежде чем станет разрешено делегирование. Фоновое выполнение отсутствует. |
| `retry_backoff_base` | int | Нет | `1` | Базовая задержка (в секундах) для экспоненциального backoff с джиттером, используемого повторными вызовами (§Разрешение конфликтов, руководство по конфигурации). |
| `retry_max_attempts` | int | Нет | `3` | Максимальное количество повторных вызовов после `hash_mismatch` перед тем, как Документатор эскалирует ситуацию оператору вместо повторной попытки. |
| `temperature` | float | Нет | `0.1` | Случайность генерации LLM; более высокие замечания увеличивают разнообразие (диапазон: 0.0–2.0). Применяется для каждого агента роли (§Нулевые скрытые замечания по умолчанию, layer-1.md). |
| `top_p` | float | Нет | `0.9` | Параметр выборки ядра; токены с кумулятивной вероятностью ниже этого порога исключаются (диапазон: 0.0–1.0). Применяется для каждого агента роли (§Нулевые скрытые замечания по умолчанию, layer-1.md). |
| `sync_latency_budget_ms` | int | Нет | `30000` | Максимальная продолжительность в миллисекундах для синхронного вызова `delegate()`. Вызов, превышающий этот бюджет, возвращает структурированную ошибку тайм-аута, а не блокируется бесконечно. |
| `frequency_penalty` | float | Нет | `0.0` | Снижает повторение токенов; положительные замечания штрафуют повторяющиеся токены (диапазон: -2.0–2.0). Нейтральное значение по умолчанию, явно задано, а не выведено (§Нулевые скрытые замечания по умолчанию, layer-1.md). |

### Записи для каждой операции

Записи в `allowed_operations` для каждой операции имеют следующую структуру:

```yaml
# Tier 2+ operation entry (default type — no explicit type field needed):
allowed_operations:
  - type: operation          # operation | pattern — omitted defaults to "operation"
    change_type: update      # update | split | create_ru | custom
    trust_level: safe        # safe | review — must not fall below the static floor (§Trust Classification, main spec)
    targets: []              # empty = all docs; list = specific manifest IDs
    requires_diff_preview: true  # always enforced at Tier 2+

# Tier 3 pattern entry (enables auto-apply for matching changes):
  - type: pattern
    pattern_id: "auto-bump-patch"   # unique identifier for this pattern
    pattern_description: "Deterministic patch-level version bumps in CHANGELOGS/*.changes.md and index.md metadata"
    match_criteria:
      change_type: update
      file_pattern: "CHANGELOGS/*.changes.md"  # glob-style path pattern; empty = match any file
    trust_level: safe
    requires_diff_preview: true
```

Поля ввода шаблона:

| Поле | Тип | Описание |
|-------|------|-------------|
| `type` | `operation` \| `pattern` | Дискриминатор. По умолчанию используется `operation` (для обратной совместимости). |
| `pattern_id` | string | Уникальный идентификатор этого шаблона (kebab-case). |
| `pattern_description` | string | Человекочитаемое описание того, что соответствует шаблону. |
| `match_criteria.change_type` | enum | Ограничивает совпадения определённым `change_type`. |
| `match_criteria.file_pattern` | string | Шаблон пути в стиле Glob относительно корня рабочей области. `*` = любые символы, кроме `/`, `**` = любые символы, включая `/`, `?` = один символ, кроме `/`. Недействительные шаблоны отклоняются при загрузке политики. |

## Операционная настройка

Какая ручка управляет каким путём отказа. Все замечания являются полями политики из §Field Reference; для их применения не требуется изменение кода или перезапуск, кроме перезагрузки политики.

| Сбой или давление | Поле | При истощении |
|---------------------|-------|---------------|
| Одновременный `delegate()` от другого агента | `lock_wait_timeout` | Прервать до любой записи; ошибка указывает PID/IP владельца блокировки и метку времени её получения (§Протокол безопасности #2) |
| Файл изменён между сканированием и записью | `retry_backoff_base` + `retry_max_attempts` | Эскалировать оператору; повторно запустить `audit()` для получения нового `audit_id` |
| Оператор отсутствует, пока показывается diff | `operator_approval_timeout` | Выдать `error_category: operator_timeout`; ничего не записывается, временные `.tmp` файлы отбрасываются |
| Ожидание внеканальных оповещений | `notification_mode` | Не применимо — асинхронный канал отсутствует; см. §Семантика оповещений |
| Полное повторное сканирование превышает количество документов | `rescan_batch_ceiling` | Ответ включает `has_remaining: true` и `scan_cursor`; оператор повторно вызывает `audit(scan_cursor=<value>)` для продолжения с места, где остановилось предыдущее выполнение |
| Представлен устаревший, недействительный или неполный `audit_id` в `delegate()` | `audit_freshness` | Отклонить с `error_category: audit_mismatch` (реестр отсутствует/истёк/несоответствие области) или `error_category: blocking_finding` (присутствуют высокие/критические находки или сканирование не завершено, `has_remaining: true`) и действием повторного запуска `audit()`. Если реестр отсутствует/недоступен, FAILS CLOSED — все записи запрещены до аутентифицированного отмены через `documenter.override_gate(reason, operator_id)` |

### Семантика уведомлений

Документатор не имеет подсистемы уведомлений: нет таймера, нет демона, нет канала push-уведомлений, нет фонового опроса (см. §Цель и §Семантика одобрения, основной спецификации). Любой сигнал, видимый оператору — отчёт аудита, предварительный просмотр разницы, запрос разрешения конфликта блокировки, запрос одобрения — генерируется в рамках синхронного ответа на вызов, который его породил, и дополнительно сохраняется в неизменяемый журнал событий (§Схема событий, руководство по конфигурации) для последующего воспроизведения. Поле `notification_mode` существует, чтобы сделать это явным и зарезервировать пространство имён: введение асинхронного канала потребовало бы изменения модели в основной спецификации, а не редактирования политики, и требовало бы нового замечания `notification_mode` вместе с определённым контрактом доставки.

## Процесс авторизации

Порядок предоставления прав на запись. Каждый шаг представляет собой отдельное действие оператора; Документатор никогда не выполняет шаги самостоятельно. Шаги 1–3 предшествуют первому вызову уровня Tier 2+; в основном спецификации §Trust Tiers указано, что файл политики и брифинг являются обязательными предварительными условиями.

1. **Аудит на текущем уровне.** Запустите `audit("*")` и устраните замечания на уровнях `high` и `critical`. Уровень 2+ на несоответствующем корпусе автоматизирует дрейф, а не очистку.
2. **Создайте файл политики.** Создайте `documenter_policy.yml` согласно §Файл политики: установите допустимые комбинации `change_type` + `trust_level` + `targets` в `allowed_operations` и настройте операционные параметры согласно §Операционная настройка.
3. **Проверьте офлайн.** Загрузите кандидатский файл в режиме только проверки. Загрузка завершается ошибкой, если: `allowed_operations` не пуст ниже уровня 2 (правило валидатора), `trust_level` ниже выведенного порога для его `change_type` (правило авторитета) или значение `notification_mode` не распознано.
4. **Запишите брифинг.** Напишите и архивируйте брифинг оператора — в котором задокументированы документы и замечания `change_type`, переданные в делегирование, максимальное количество документов, к которым может обратиться один вызов, и процедура отмены — затем установите `briefing_ref` в путь к нему. Этот Артефакт является читаемой человеком counterpartой `allowed_operations`.
5. **Повысьте уровень.** Установите `active_tier` в том же редактировании, что и `briefing_ref`, чтобы частичное редактирование не могло оставить уровень 2+ без ссылки на брифинг.
6. **Первая запись на новом уровне.** Вызовите `delegate()` для одной низко-рисковой цели с новым `audit_id`. Просмотрите изменения по пунктам независимо от уровня; уровень 2 предоставляет возможности, а не снижает тщательность проверки.
7. **Оцените для уровня 3.** Повышайте уровень только на основе задокументированных доказательств: ≥90% одобрений на уровне 2 за предшествующие две недели журнала событий (§Руководство по выбору уровня, основной спецификации), вычисляемое из полей `decision` в журнале событий (§Схема событий, руководство по конфигурации). Затем одобренные шаблоны явно перечисляются в `allowed_operations` с использованием записей `type: pattern` с `pattern_id`, `pattern_description` и `match_criteria` (§Записи для каждой операции); уровень 3 никогда не выводит шаблон, который оператор не авторизовал.

**Откат:** установите `active_tier` в меньшее значение. Изменение вступает в силу при следующем вызове; выполняющийся `delegate()` завершается на том уровне, на котором он был принят, удерживая блокировку на уровне операции в соответствии с §Протоколом безопасности #2.
