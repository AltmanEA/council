## Назначение и условие о едином источнике

Это руководство разбивает Документатор на части и предписывает, **как каждая
часть реализована**: детерминированный скрипт в `tools/`, AI-промпт (текст
навыка) или внешний движок. Обязывающее правило (позиция эволюции, `index.md`):
всё, что может быть алгоритмизировано, реализуется детерминированно с помощью
скрипта; суждение остаётся за промптом.

Этот документ предписывает, КАК реализуются механизмы `docs/en/documenter-service/index.md`
(спецификация концепции) и `.agents/skills/documentation/SKILL.md` (навык)
**Документатора**. Он **не** переопределяет их поведение. Если это руководство и
указанные документы кажутся противоречащими друг другу, указанные документы имеют
приоритет, а это руководство исправляется. Правила цитируются ссылками, а не пересказываются.

## Матрица инвентаря компонентов и распределения

Каждая часть помечена: **script** (детерминированный скрипт в `tools/`), **prompt**
(текст навыка / суждение агента), **external** (движок Проекта перевода) или
гибрид.

| Часть | Форма | Артефакт-владелец |
|---|---|---|
| Навык Documentation Worker — ядро оркестрации | prompt | `.agents/skills/documentation/SKILL.md` |
| Генерация манифеста | script | `tools/gen_manifest.py` (единственный автор манифеста) |
| Движок аудита | script | `tools/check_all.py` (замороженный контракт, Фаза 0 выполнена) |
| Писатель версии/чанелога/манифеста | script | `tools/bump_version.py` (атомарный, упорядоченный) |
| Предложение классификации bumps | script (только чтение) | `tools/classify_bump.py` |
| Судья структурного дрейфа EN↔RU + write-гейты | script | `tools/check_drift.py` (гейты `--phase4` выполнены, Фаза 1) |
| Генерация перевода | external | `techdoc-translator` через `defaults/translation.lock` (ADR-014) |

| Грамматика одобрения (`approve` / `approve: <object>`) | prompt | действие оператора (OP-1), привязано к карточке |

| Стейджинг для сложных правок | prompt procedure + gitignored area | `sessions/<id>/staging/` |

## Соответствие возможностей шагам цикла

Навык является единственным автором (AGENTS.md §2) и выполняет каждый шаг операционного цикла
`index.md` §Operating model:

| Шаг цикла | Действие навыка | Форма |
|---|---|---|
| 1 Предложение + упаковка | собрать changeset (стейджинг, если сложно), один пакет в один коммит | prompt |
| 2 Консультативный аудит | запустить `check_all.py`; объединить вердикт с карточкой | script |
| 3 Проверка оператором + `approve` | отобразить Карточку согласования; ждать ответа в чате | prompt + оператор |
| 4 Запись | запустить писателей в порядке (контент → changelog → manifest) | script |
| 5 Пост-коммитный аудит / откат | оператор запускает `check_all.py`; `git revert` | script + оператор |

## Детерминированное ядро (скрипты)

- **Движок аудита `check_all.py`** — замороженный контракт (`index.md` §Audit tool):
  код выхода `0` чисто / `1` замечания / `2` критично; замечания никогда не блокируют (OP-3).
  Рендеринг: чисто — без вывода; иначе `⚠ findings: N` или `🚨 critical: N`
  плюс однострочные подсказки по исправлению, сгруппированные и отсортированные по серьёзности. Флаг
  `--severity` сохраняет семантику фильтра (минимальный отображаемый уровень серьёзности; по умолчанию
  `low` согласно поправке оператора Фазы 0). **Контракт токенов** (стабильный, пригодный для grep в
  хуке): литеральные токены `severity=high|medium|low` в человекочитаемом выводе и схема
  `--json`; маркеры `⚠`/`🚨` только визуальные, не цели для grep.
  Фактическое поведение соответствует этому контракту
  (Фаза 0 выполнена).
- **Манифест** — `gen_manifest.py --write` является единственным автором; `--check`
  проверяет паритет. Ручное редактирование запрещено (documentation-rules §2.2).
- **Запись версии** — `bump_version.py` владеет нормативным порядком content →
  changelog → manifest, атомарно с откатом. Скрипты обеспечивают атомарность, а не
  власть: запускаются только навыком после Approve.
- **Судья EN↔RU `check_drift.py`** — единственный структурный компаратор со стороны Совета;
  с Фазы 1 также содержит детерминированные write-гейты перевода Фазы-4
  в виде идентификаторов правил `phase4-fail` (отчет fail == 0), `phase4-parity` (1:1
  паритет строк), `phase4-identity` (отклонение копии EN), `phase4-glossary` (совпадение
  терминов глоссария). Результаты гейтов вычисляются в коде, никогда не выводятся заново
  агентом из текста.
- **Провенанс** — `translation_status.py` перестраивает сайдкары + `STATUS.md`
  из отчетов запусков; строка `Translations:` карточки выводится из `STATUS.md`
  в момент генерации карточки.

## Промпт-части (навык и суждение агента)

Зарезервировано за суждением (никогда не скриптуется): семантическая переработка контента;
предложение механической/семантической классификации (семантическая слепота —
принятый риск — именование оператором семантических одобрений является вынуждающей
функцией); соответствие глоссарию (documentation-rules §8 правило 3); согласованность
абстракции (правило 5); классификация сирот. Навык остаётся единственным
автором `docs/`, `docs-manifest.yaml`, `CHANGELOGS/`.

## Карточка согласования (чат-артефакт акта одобрения)

Фиксированный шаблон: максимум 10 строк (обычно 6–8), фиксированные порядок и метки;
карточки переменного формата запрещены:

```
Files: <affected files, max 8 per line>
Category: <create | update | delete | split | translation>
Delta: +<N> / −<M> / net ±<K>
Classification: <mechanical | semantic> [agent proposed: <original>]
Audit: <omitted when clean; else ⚠ findings: N / 🚨 critical: N + hints>
Translations: <mode> · verified <N> · unverified <M>   # only if translation involved
State: <final | intermediate>                          # staged work only
```

- Скобка `Classification` появляется только при переопределении оператора (облегчённый
  журнал переопределений). Строка `Audit` полностью отсутствует при чистом аудите
  (silent-when-clean). `State: intermediate` предупреждает, что карточка привязана к не
  полностью собранному пакету; одобрение привязывается к `final`.
- Ключ интерпретации `Translations`: `M = 0` → действий не требуется; `M > 0` → дрейф
  требует внимания оператора.
- Терминология: **Карточка согласования (Approval Card)** (решение оператора,
  sess-documenter-impl-design 2026-11-19). Устаревший термин глоссария
  «Поверхность оператора» не используется; не путать с «Точкой входа оператора»
  (Operator Ingress, Слой 2 Совета, ADR-018).

## Грамматика approve

(a) Голый `approve` одобряет механическое изменение. (b) Семантическое изменение
требует `approve: <noun phrase>` с указанием его объекта. (c) Граничные случаи:
повышение версии + запись чанелога = механическое; добавление термина в глоссарий = семантическое.
(d) Агент всегда отображает классификацию как помеченное поле карточки, никогда
не пряча её в прозе; оператор может переопределить.

## Простота и вытеснение (руководство)

Фиксированного числового потолка на инструменты нет. В рамках OP-1 оператор оценивает
каждое добавление по существу при утверждении; сложность — это решение, а не порог.
Вытеснение — замещение, а не добавление — остаётся рекомендуемым подходом, когда
возможность можно встроить в существующий инструмент, но не является требованием,
и его отсутствие не служит основанием для эскалации.

Историческая заметка: `tools/check_parity.py` был упразднён, когда его правила
`phase4-*` перешли в `check_drift.py` (Фаза 1). Это фиксация произошедшего,
а не правило.

## Фазирование

- **Фаза 0 (предварительное условие, один атомарный changeset):** переписать `check_all.py` на
  замороженный контракт кодов выхода + рендеринг; синхронизировать все прозаические контракты
  в том же коммите (`tools/README.md`, примечание `index.md` о статусе реализации,
  **Контрольный список соответствия** навыка). Никакие новые скрипты не принимаются до этого. Переключение
  хука warn→block — только после завершения Фазы 0 и прохождения базовой линии.
- **Фаза 1:** добавить правила гейтов `phase4-*` в `check_drift.py`; удалить
  `check_parity.py`; добавить столбец `Contract` в таблицу инструментов
  `tools/README.md` (реестр прозаических контрактов); очистить прозаические ссылки.
- **Фаза 2:** принять шаблон Карточки согласования и грамматику approve в
  процедуру шага-(5) навыка.
- **Фаза 3:** данное руководство принимается как нормативное посредством
  approved changeset, который его создаёт.

## Определение готовности

По части **script**: (a) dry-run на фикстурах в `tools/tests/fixtures/`;
(b) как минимум один запуск против живого корпуса документации; (c) после
Фазы 0: один полный базовый замер `check_all.py --strict` зафиксирован до начала
soak-режима хука; 10 чистых коммитов soak предшествуют любому переключению в блокирующий режим.
По части **prompt**: скриптовый dry-run цикла плюс разовый
приемочный тест новым оператором-человеком — второй оператор завершает полный
операционный цикл, используя только это руководство и навык.

## Синхронизация прозаических контрактов

Поведенческий контракт каждого инструмента регистрируется записью в столбце `Contract`
таблицы инструментов `tools/README.md` (канонический якорь: раздел README, раздел
навыка или пункт спецификации). Согласно AGENTS.md §1.7, любое изменение поведения инструмента
ОБЯЗАНО обновлять текст зарегистрированного контракта в том же changeset; аудит
списка файлов changeset проверяет это, новый инструмент для этого не создаётся.

## Разделение конвейера перевода

Движок — «чёрный ящик» (файл блокировки, `--contract-version`, отказо-закрытые коды
выхода 0–6 в `docs/en/translation-project/`). Совет владеет: подготовкой входных данных
(глоссарий, skip-patterns), детерминированной проверкой (четыре гейта
`phase4-*` в `check_drift.py`), артефактами провенанса и режимом drift-аудита (режим
(c) запускает только `check_drift.py` — no-rule-fork, documentation-rules §8).
Навык повторно выполняет проверку после генерации и перед любой записью; он никогда не
оценивает результаты гейтов, читая прозу.

## Инвариант единого коммита и стейджинг

Владение единственное: упаковка и порядок content → changelog → manifest
принадлежат `bump_version.py` / `gen_manifest.py`; стейджинг размещается в
gitignored области `sessions/<id>/staging/` вне дерева `docs/`.
Поле `State:` Карточки согласования — структурная защита от одобрения частичных
пакетов. Другие разделы ссылаются на этот, никогда не пересказывая его.
